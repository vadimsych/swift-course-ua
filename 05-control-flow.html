Керування потоком виконання

Цикли, if і switch (зокрема як вирази), зіставлення зі зразком, if case, передача керування, мітки, guard, defer і перевірка доступності API.

У книзі: controlflow

Цикл for-in

for-in проходить по будь-якій послідовності: масиву, словнику, діапазону, рядку.

Swift
for level in 1...3 {
    print("Рівень \(level)")
}

for _ in 0..<3 {          // значення не потрібне
    spawnEnemy()
}

let bonuses = ["gold": 50, "gems": 3]
for (kind, amount) in bonuses {
    print(kind, amount)
}

Класичного C-подібного for (int i = 0; i < n; i++) у Swift немає. Цикл по діапазону завжди йде з кроком 1, а для іншого кроку (через 25, назад) використовують функцію stride — вона створює послідовність чисел, по якій іде цикл:

Swift
for page in stride(from: 1, to: 100, by: 25) {
    print(page)          // 1 26 51 76 — до 100, саме 100 не включається
}

for countdown in stride(from: 3, through: 1, by: -1) {
    print(countdown)     // 3 2 1 — включно з кінцевим
}

Різниця лише в одному слові: to — «до, не доходячи», through — «до, включно».

C# Swift
for (int i = 0; i < n; i++) for i in 0..<n
for (int i = 0; i <= n; i++) for i in 0...n
for (int p = 1; p < 100; p += 25) for p in stride(from: 1, to: 100, by: 25)
for (int c = 3; c >= 1; c--) for c in stride(from: 3, through: 1, by: -1)

Змінна циклу — константа: змінити i всередині тіла не можна.

Цикли while

while

Перевіряє умову перед кожною ітерацією:

Swift
var energy = 10
while energy > 0 {
    energy -= 3
}

repeat-while

Аналог do-while: тіло виконується хоча б раз, умова — наприкінці.

Swift
var roll: Int
repeat {
    roll = Int.random(in: 1...6)
} while roll != 6

Умовні інструкції

if

Swift
let battery = 0.15
if battery < 0.1 {
    enterLowPowerMode()
} else if battery < 0.2 {
    showBatteryWarning()
} else {
    hideBatteryWarning()
}

if може бути виразом: кожна гілка дає значення, і всі гілки — одного типу.

Swift
let icon = if battery < 0.1 { "battery.0" }
           else if battery < 0.5 { "battery.50" }
           else { "battery.100" }

func label(for battery: Double) -> String {
    if battery < 0.2 { "Зарядіть пристрій" } else { "OK" }   // вираз як результат функції
}

Щоб if став виразом, кожна його гілка мусить бути одним значенням — або гілкою, з якої виконання не повертається (throw, fatalError). else обов'язковий: значення має бути в будь-якому разі. Коли гілки дають літерали різних типів, підкажи тип анотацією:

Swift
let limit: Double = if isPremium { 100 } else { 50.5 }
let badge: String? = if isPremium { "PRO" } else { nil }   // nil потребує опціонального типу

switch

switch порівнює значення з набором зразків і виконує першу гілку, що збіглася.

Swift
let key: Character = "w"
switch key {
case "w", "W":
    moveUp()
case "s":
    moveDown()
default:
    break
}

Правила, що відрізняються від C#:

  • Вичерпність. Кожне можливе значення має бути покрите. Для Int чи String це означає default, а для enum можна перелічити всі варіанти без default.
  • Немає неявного провалювання. Після гілки виконання виходить зі switch, break писати не треба. Порожня гілка заборонена — якщо нічого робити не треба, пиши break.
  • Кілька значень в одній гілці — через кому.
  • default може бути лише один і мусить стояти останнім.
  • Коментар не рахується як інструкція: гілка лише з коментарем усе одно порожня.

switch теж може бути виразом:

Swift
let speed = switch terrain {
    case .road: 1.0
    case .grass: 0.7
    case .swamp: 0.3
}

Інтервали

Swift
let ping = 87
let quality = switch ping {
    case ..<50: "відмінно"
    case 50..<120: "нормально"
    case 120...: "погано"
    default: "?"   // для Int компілятор не доводить вичерпність діапазонів
}

Кортежі

Кортеж перевіряється по всіх елементах; _ означає «будь-що». Зручно, коли рішення залежить від кількох значень одразу:

Swift
let access = (isLoggedIn: true, isSubscribed: false, trialDays: 3)

switch access {
case (false, _, _):
    print("Запропонувати вхід")
case (true, true, _):
    print("Повний доступ")
case (true, false, 1...7):
    print("Пробний період")
case (true, false, _):
    print("Показати paywall")
}

Якщо кілька гілок підходять, виконується перша. Тут гілки покривають усі можливі комбінації, тож default не потрібен — компілятор доводить вичерпність для Bool і _.

Прив'язування значень

У гілці можна дістати частину значення в константу (або var) і використати її в тілі:

Swift
let response = (status: 404, retryAfter: 30)

switch response.status {
case 200..<300:
    print("Успіх")
case let code where code == 429 || code >= 500:
    print("Повторимо через \(response.retryAfter) с, код \(code)")
case let code:
    print("Помилка клієнта \(code)")   // будь-яке інше значення
}

Гілка case let code: збігається з будь-яким значенням, тому default не потрібен — він був би недосяжним.

where

Додаткова умова для гілки. Розберемо жест свайпу за зсувом по осях:

Swift
let swipe = (dx: -120.0, dy: 8.0)

switch swipe {
case let (dx, dy) where abs(dx) > abs(dy) * 3:
    print(dx < 0 ? "Свайп ліворуч" : "Свайп праворуч")
case let (dx, dy) where abs(dy) > abs(dx) * 3:
    print(dy < 0 ? "Свайп угору" : "Свайп униз")
default:
    print("Діагональ — ігноруємо")
}

Складені гілки

Кілька варіантів, для яких код однаковий, перелічують через кому: case "w", "up": означає «"w" або "up"».

Те саме працює й тоді, коли варіанти несуть дані. Наприклад, дотик буває звичайним і довгим, і обидва мають координати:

Swift
enum Input {
    case tap(x: Double, y: Double)
    case longPress(x: Double, y: Double)
    case key(Character)
}

let input = Input.longPress(x: 40, y: 300)

switch input {
case .tap(let x, let y), .longPress(let x, let y):
    print("Дотик у точці \(x), \(y)")    // x і y є в обох варіантах
case .key(let c):
    print("Клавіша \(c)")
}

Правило: тіло гілки одне на всі варіанти, тож у ньому мають бути доступні ті самі змінні, хоч би який варіант спрацював. Тому кожен варіант мусить дати однакові імена однакових типів. Так не можна:

Swift
case .tap(let x, let y), .key(let c):   // ❌ якщо прийшов .key, змінних x і y немає
C#

Pattern matching у C# 8+ (switch expression, when, tuple patterns) близький за можливостями. Swift-аналоги: where = when, case let = declaration pattern, _ = discard. Головне, що в Swift це було з першої версії і switch завжди вичерпний.

Зразки поза switch: if case і for case

Буває, що з усіх варіантів enum цікавить лише один. Писати заради нього цілий switch з порожнім default незручно:

Swift
enum Reward {
    case coins(Int)
    case item(String)
    case nothing
}

let reward = Reward.coins(30)

switch reward {
case .coins(let amount) where amount > 10:
    print("Багато монет: \(amount)")
default:
    break                                  // усе інше не цікавить
}

if case — це той самий switch, але на одну гілку:

Swift
if case .coins(let amount) = reward, amount > 10 {
    print("Багато монет: \(amount)")
}

Як читати:

if case  .coins(let amount)  =  reward  ,  amount > 10
         └── зразок ───────┘    └ що ┘     └ додаткова умова ┘

Знак = тут — не присвоєння, а «зіставити з». Читай так: «якщо reward має вигляд .coins(щось), поклади це щось в amount, і якщо amount > 10 — виконай блок». Для .item чи .nothing умова просто хибна.

Чому не можна написати if reward == .coins: .coins без числа — неповне значення, порівнювати нема з чим. До того ж нам треба ще й дістати число. if case робить і перевірку, і витягування.

Те саме працює в guard і for:

Swift
guard case .coins(let amount) = reward else { return }   // далі amount доступний

let rewards: [Reward] = [.coins(5), .item("key"), .coins(40)]
for case .coins(let n) in rewards where n >= 10 {
    print(n)       // тільки монетні нагороди від 10: 40
}

let maybeScores: [Int?] = [10, nil, 30]
for case let score? in maybeScores {
    print(score)   // 10, 30 — пропускаємо nil
}
C#

Найближче — pattern matching через is: if (reward is Coins { Amount: > 10 } c). У Swift зразок стоїть ліворуч від =, а значення — праворуч.

Передача керування

continue, break, fallthrough, return і throw (останні два — в уроках про функції й помилки).

continue

Переходить до наступної ітерації:

Swift
for name in players {
    if name.hasPrefix("bot_") { continue }
    print(name)
}

break

У циклі — одразу завершує цикл.

У switch — завершує switch. Головне застосування — порожня гілка, яку треба явно позначити:

Swift
switch command {
case "quit": exitGame()
case "pause": pause()
default: break   // ігноруємо невідомі команди
}

fallthrough

Коли потрібно, щоб після однієї гілки виконалась і наступна, пишуть fallthrough. Умову наступної гілки він ігнорує — просто продовжує в її тілі. Перейти так у гілку з let-прив'язуванням не можна: значень для неї ніхто не підготував.

Swift
var perks: [String] = []
switch tier {
case 3:
    perks.append("золота рамка")
    fallthrough
case 2:
    perks.append("бонусний XP")
    fallthrough
case 1:
    perks.append("без реклами")
default:
    break
}
C#

C# забороняє неявне провалювання з непорожньої гілки і вимагає goto case. Swift також забороняє, а явний інструмент — fallthrough.

Інструкції з мітками

Для вкладених циклів можна вказати, який саме цикл перервати чи продовжити:

Swift
search: for row in grid {
    for cell in row {
        if cell == target {
            print("Знайдено")
            break search      // виходимо з обох циклів
        }
        if cell == 0 { continue search }   // наступний рядок
    }
}

Мітка працює й для switch всередині циклу: break без мітки там зупинить лише switch, а break loopName — цикл. Мітку можна поставити й на if чи switch, щоб вийти з них через break мітка (звичайний break з if не виходить).

Ранній вихід: guard

guard перевіряє умову і, якщо вона хибна, виконує else, який мусить покинути поточну область видимості (return, break, continue, throw або виклик функції, що не повертається).

Swift
func startMatch(players: [String], map: String?) {
    guard players.count >= 2 else {
        print("Замало гравців")
        return
    }
    guard let map else {
        print("Мапу не обрано")
        return
    }
    print("Старт на \(map) для \(players.count) гравців")   // map тут String
}

Константи, прив'язані в guard, доступні до кінця функції. Так «щасливий шлях» іде вздовж лівого краю, а не тоне у вкладених if.

C#

Це формалізований early return: if (x == null) return;. Різниця в тому, що компілятор гарантує вихід з else і розгортає опціонал для решти коду.

Відкладені дії: defer

defer { ... } означає «виконай цей код наприкінці, коли виходитимеш з поточного блоку», хоч би як ти з нього вийшов: через return, break, кинуту помилку чи просто дійшовши до кінця.

Swift
func loadLevel() {
    showSpinner()
    defer { hideSpinner() }

    guard let data = readFile() else { return }
    parse(data)
}

Порядок виконання:

  1. showSpinner() — спінер показано.
  2. defer { hideSpinner() } — нічого не виконується. Swift лише запам'ятовує, що зробити перед виходом.
  3. Якщо файл не прочитався, спрацює return, а перед самим виходом — hideSpinner().
  4. Якщо прочитався, виконається parse(data), функція дійде до кінця, і перед виходом — hideSpinner().

Без defer довелося б писати hideSpinner() перед кожним return. Варто комусь додати ще один вихід і забути про це — спінер зависне на екрані.

Swift
func loadLevel() {
    showSpinner()
    guard let data = readFile() else {
        hideSpinner()          // не забути тут
        return
    }
    parse(data)
    hideSpinner()              // і тут
}

Деталі:

  • кілька defer виконуються у зворотному порядку: останній оголошений — першим;
  • defer спрацьовує при виході з поточного блоку: у циклі — наприкінці кожної ітерації, в if — при виході з if;
  • усередині defer не можна робити return чи break;
  • при краху застосунку defer не виконується.
C#

Це аналог try { ... } finally { HideSpinner(); }, тільки без обгортання коду в try, і пишеться одразу поруч з тим, що треба «прибрати»: показав спінер — наступним рядком сказав, що його треба сховати.

Перевірка доступності API

Щоб використати API новішої ОС, ніж мінімальна версія застосунку, перевір доступність:

Swift
if #available(iOS 18, macOS 15, *) {
    useNewFeature()
} else {
    useFallback()
}

guard #available(iOS 17, *) else { return }

if #unavailable(iOS 16) {
    applyLegacyWorkaround()
}

* означає «на всіх інших платформах — мінімальна версія таргета». Після guard #available(...) else { return } компілятор вважає новіше API доступним до кінця області видимості. Компілятор перевіряє, що ти не викликаєш нове API поза такою перевіркою. Для цілих типів і функцій є атрибут @available(iOS 18, *) (урок про атрибути).

Порада

Ти вже знаєш цю ситуацію з StoreKit 2 і fallback на StoreKit 1. У нативному коді це робиться саме через #available і @available, а компілятор не дасть забути гілку для старої ОС.

Практика
  1. Напиши switch над кортежем (isLoggedIn: Bool, hasSubscription: Bool, trialDaysLeft: Int), що повертає (як вираз) один з рядків: "гість", "підписник", "пробний період", "пробний закінчився".
  2. Знайди в двовимірному масиві першу клітинку зі значенням 0 і вийди з обох циклів через мітку.
  3. Перепиши функцію з трьома вкладеними if let на guard.
  4. Додай два defer у функцію з print і переконайся, в якому порядку вони виконуються.
