Мова крок за кроком · урок 24

Узагальнення

Generic-функції й типи, обмеження типів, асоційовані типи в протоколах, where-умови в різних місцях, generic-сабскрипти, неявні обмеження Copyable і noncopyable-типи.

У книзі: generics

Яку проблему розв'язують узагальнення

Уяви, що ти написав утиліту для масиву ID і вона працює. А потім та сама задача з'являється для [Product], для [URL], для [String]:

Swift
func firstDuplicate(_ items: [Int]) -> Int? { /* ... */ nil }
// firstDuplicate(products)     // помилка: очікується [Int]

Копіювати функцію під кожен тип — шлях до розбіжностей і багів. Узагальнення дозволяє описати алгоритм один раз і сказати, що саме алгоритму потрібно від типу елементів. Стандартна бібліотека майже повністю така: Array<Element>, Dictionary<Key, Value>, Optional<Wrapped>, Result<Success, Failure>.

Generic-функції

Swift
func firstDuplicate<T: Hashable>(_ items: [T]) -> T? {
    var seen = Set<T>()
    for item in items {
        if !seen.insert(item).inserted { return item }
    }
    return nil
}

firstDuplicate([3, 8, 1, 8])            // 8
firstDuplicate(["a", "b", "a"])         // "a"

<T: Hashable> — список параметрів типу. Конкретний тип T визначається в місці виклику з аргументів.

Параметри типу

Параметр типу — заповнювач для конкретного типу. Він може використовуватися як тип параметрів, результату і всередині тіла. Параметрів може бути кілька: <Key, Value>.

Іменування параметрів типу

Порада з практики: якщо параметр має роль, дай йому ім'я цієї ролі (Element, Key, Payload, Model) — у сигнатурі на кшталт func cache<Key, Payload> одразу видно, що до чого. Однолітерні T/U лишай для коротких допоміжних функцій, де роль очевидна. Пишуться імена як типи — з великої літери.

Generic-типи

Власні класи, структури й enum теж можуть бути узагальненими:

Swift
struct RingBuffer<Element> {
    private var storage: [Element?]
    private var head = 0
    private(set) var count = 0

    init(capacity: Int) {
        storage = Array(repeating: nil, count: capacity)
    }

    mutating func write(_ value: Element) {
        storage[(head + count) % storage.count] = value
        if count < storage.count { count += 1 } else { head = (head + 1) % storage.count }
    }

    mutating func read() -> Element? {
        guard count > 0 else { return nil }
        defer { head = (head + 1) % storage.count; count -= 1 }
        return storage[head]
    }
}

var lastFrames = RingBuffer<Double>(capacity: 3)
lastFrames.write(16.6)
lastFrames.write(17.1)
lastFrames.read()   // 16.6

Тип можна вказати явно (RingBuffer<Double>) або дати компілятору вивести його.

Розширення generic-типу

У розширенні не повторюють список параметрів: параметри з оригінального оголошення доступні за тими самими іменами:

Swift
extension RingBuffer {
    var isFull: Bool { count == storage.count }
    var newest: Element? {
        count == 0 ? nil : storage[(head + count - 1) % storage.count]
    }
}

Обмеження типів

Часто потрібно, щоб тип щось умів: порівнюватися, хешуватися, відповідати протоколу або бути підкласом.

Синтаксис

Swift
func show<V: UIView, M: Decodable>(_ view: V, model: M) { }   // V — підклас UIView, M — відповідає протоколу

Обмеження в дії

Swift
func indexOfMax<T: Comparable>(_ values: [T]) -> Int? {
    guard var best = values.indices.first else { return nil }
    for i in values.indices where values[i] > values[best] {
        best = i
    }
    return best
}

indexOfMax([3.2, 9.9, 1.0])     // 1
indexOfMax(["b", "z", "a"])     // 1

Без T: Comparable оператор > не скомпілювався б: компілятор не знає, чи довільний T можна порівнювати.

C#

Те саме, що where T : IComparable<T> у C#, тільки обмеження пишеться одразу в дужках: <T: Comparable>.

Асоційовані типи

Протокол може мати асоційований тип — заповнювач, який визначає тип, що реалізує протокол.

Swift
protocol Repository {
    associatedtype Entity
    func all() async throws -> [Entity]
    func save(_ entity: Entity) async throws
}

Асоційовані типи в дії

Swift
struct Note { let text: String }

final class InMemoryNotes: Repository {
    private var notes: [Note] = []
    func all() async throws -> [Note] { notes }        // Entity виведено як Note
    func save(_ entity: Note) async throws { notes.append(entity) }
}

Компілятор виводить Entity = Note з сигнатур методів. Можна вказати явно: typealias Entity = Note.

C#

Найближчий аналог — generic-інтерфейс IRepository<TEntity>. Різниця в тому, що з асоційованим типом тип InMemoryNotes реалізує протокол один раз з одним конкретним Entity, а в C# клас може реалізувати IRepository<A> і IRepository<B> одночасно. Асоційовані типи визначає реалізація, а не той, хто використовує протокол.

Розширення існуючого типу для асоційованого типу

Якщо існуючий тип уже має потрібні члени, відповідність оголошується порожнім розширенням, а асоційований тип компілятор виводить сам з наявних сигнатур:

Swift
protocol Emptiable {
    associatedtype Value
    var isEmpty: Bool { get }
    var first: Value? { get }
}

extension String: Emptiable { }   // Value виведено як Character з властивості first
extension Set: Emptiable { }      // Value виведено як Element

Обмеження на асоційований тип

Swift
protocol Cache {
    associatedtype Key: Hashable
    associatedtype Value
    subscript(key: Key) -> Value? { get set }
}

Протокол в обмеженнях власного асоційованого типу

Асоційований тип може вимагати відповідності тому самому протоколу. Так описують рекурсивні структури:

Swift
protocol TreeNode {
    associatedtype Child: TreeNode
    var children: [Child] { get }
}

struct MenuItem: TreeNode {
    let title: String
    var children: [MenuItem]     // Child == MenuItem
}

Generic where

where перед тілом задає додаткові вимоги: відповідність протоколу, рівність типів, суперклас.

Swift
func groupByKey<S: Sequence, Key>(_ items: S, key: (S.Element) -> Key) -> [Key: [S.Element]]
    where Key: Hashable, S.Element: Identifiable
{
    Dictionary(grouping: items, by: key)
}

Розширення з where

Розширення може додавати члени лише для тих конкретизацій типу, що задовольняють умову:

Swift
extension RingBuffer where Element: Numeric {
    func sum() -> Element {
        var total: Element = 0
        var copy = self
        while let v = copy.read() { total += v }
        return total
    }
}

extension RingBuffer where Element == String {
    func joined() -> String {
        var copy = self, parts: [String] = []
        while let v = copy.read() { parts.append(v) }
        return parts.joined(separator: " ")
    }
}

RingBuffer<Double> має sum(), але не joined(). RingBuffer<String> — навпаки.

Контекстні where

where можна поставити на окремий член generic-типу, не створюючи окремого розширення:

Swift
extension RingBuffer {
    func contains(_ value: Element) -> Bool where Element: Equatable {
        var copy = self
        while let v = copy.read() { if v == value { return true } }
        return false
    }

    func longest() -> String? where Element == String {
        var copy = self, best: String?
        while let v = copy.read() where v.count > (best?.count ?? -1) { best = v }
        return best
    }
}

Асоційовані типи з where

Swift
protocol Paginated {
    associatedtype Page: Sequence where Page.Element: Decodable
    func page(_ number: Int) async throws -> Page
}

Протокол-нащадок може уточнити асоційований тип батьківського:

Swift
protocol NumberRepository: Repository where Entity: Numeric { }

Generic-сабскрипти

Сабскрипт може мати власні параметри типу й where:

Swift
extension Dictionary where Key == String {
    subscript<T>(key: String, as type: T.Type) -> T? {
        self[key] as? T
    }
}

let payload: [String: Any] = ["price": 4.99, "trial": true]
payload["price", as: Double.self]   // Optional(4.99)
payload["trial", as: String.self]   // nil

Неявні обмеження і noncopyable-типи

У generic-коді є вимога, яку ти ніколи не пишеш: параметр типу має бути копійованим (Copyable). Звичайна функція func cache<T>(_ x: T) може вільно копіювати x, бо компілятор неявно вважає T: Copyable.

Сенс з'являється, коли тип копіювати не можна. Такі типи позначають ~Copyable: значення має рівно одного власника, і компілятор стежить, щоб його не використали після передачі:

Swift
struct LicenseKey: ~Copyable {
    let value: String
    consuming func activate() -> String {   // після виклику ключ більше не існує
        value
    }
}

func redeem() {
    let key = LicenseKey(value: "ABCD-1234")
    let result = key.activate()
    // key.activate()       // помилка: ключ уже використано
    print(result)
}

Приклад навмисно всередині функції: noncopyable-значення в глобальній змінній не можна «спожити», бо глобальна змінна живе весь час роботи програми.

Щоб generic-функція приймала і копійовані, і noncopyable-типи, неявну вимогу знімають тильдою: <T: ~Copyable>. Це не означає «T некопійований», а лише «T може бути некопійованим». Відповідно, всередині такої функції копіювати значення не можна:

Swift
func describe<T: ~Copyable>(_ value: borrowing T) -> String {
    "значення типу \(T.self)"     // читати можна, копіювати — ні
}
  • borrowing — функція тимчасово отримує значення без права його знищити.
  • consuming — функція забирає значення, і після виклику у викликача його більше немає.
Порада

Noncopyable-типи — інструмент для ресурсів з унікальним власником: файлових дескрипторів, транзакцій, токенів одноразового використання. У звичайному прикладному коді вони рідкісні, але в нових системних API трапляються дедалі частіше.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Яку проблему розв'язують узагальнення?

Замість копій функції під [Int], [String] тощо пишуть одну узагальнену з потрібними обмеженнями.

2. Що надрукує цей код?

Swift
func lastTwo<T>(_ items: [T]) -> [T] {
    Array(items.suffix(2))
}

print(lastTwo(["x", "y", "z"]))

T виводиться з аргументу як String. Функція повертає масив з двох останніх елементів.

3. Чому тут помилка компіляції?

Swift
func pair<T>(_ a: T, _ b: T) -> (T, T) {
    (a, b)
}

print(pair(1, "one"))

Один параметр типу означає один конкретний тип для всіх місць, де він вжитий.

4. Яка порада щодо імен параметрів типу правильна?

Ім'я ролі робить сигнатуру зрозумілою. Імена параметрів типу пишуть як типи — з великої літери.

5. Що надрукує цей код?

Swift
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ x: Element) { items.append(x) }
    mutating func pop() -> Element? { items.popLast() }
}

func run() {
    var s = Stack<Int>()
    s.push(1)
    s.push(2)
    s.push(3)
    print(s.pop() ?? 0)
    print(s.pop() ?? 0)
}
run()

Стек повертає останній доданий елемент. ?? 0 розгортає опціонал, тож друкуються числа.

6. Як у extension RingBuffer { } звернутися до параметра типу з оголошення struct RingBuffer<Element>?

Параметри з оригінального оголошення доступні в розширенні під тими самими іменами.

7. Чому тут помилка компіляції?

Swift
func maxOf<T>(_ a: T, _ b: T) -> T {
    a > b ? a : b
}

print(maxOf(3, 7))

Обмеження <T: Comparable> дає доступ до операторів порівняння.

8. Хто визначає конкретний тип для associatedtype Entity у протоколі?

Асоційований тип — заповнювач, який заповнює тип, що відповідає протоколу.

9. Що надрукує цей код?

Swift
protocol Source {
    associatedtype Item
    func take() -> Item
}

struct Dice: Source {
    func take() -> Int { 4 }
}

print(Dice.Item.self)

Компілятор виводить Item = Int із сигнатури методу take().

10. Чому тут помилка компіляції?

Swift
protocol Cache {
    associatedtype Key: Hashable
    func value(for key: Key) -> String
}

struct Point { let x: Int }

struct PointCache: Cache {
    typealias Key = Point
    func value(for key: Point) -> String { "\(key.x)" }
}

print(PointCache().value(for: Point(x: 1)))

Обмеження associatedtype Key: Hashable діє на кожен тип, який реалізує протокол.

11. Яку вимогу не можна задати у where generic-функції?

where описує вимоги до типів, а не до значень.

12. Що надрукує цей код?

Swift
extension Array where Element: Numeric {
    func total() -> Element {
        reduce(0, +)
    }
}

print([1.5, 2.5].total())

Масив Double задовольняє Element: Numeric, тож має total(). Сума Double друкується як 4.0.

13. Що станеться з цим кодом?

Swift
struct Bag<T> {
    var items: [T]
    func has(_ x: T) -> Bool where T: Equatable {
        items.contains(x)
    }
}

struct Token { let id: Int }

let bag = Bag(items: [Token(id: 1)])
print(bag.has(Token(id: 1)))

Контекстний where робить метод доступним лише для деяких конкретизацій Bag.

14. Що означає protocol NumberRepository: Repository where Entity: Numeric { }?

Протокол-нащадок може додати обмеження на асоційований тип батьківського протоколу.

15. Що надрукує цей код?

Swift
extension Dictionary where Key == String {
    subscript<T>(key: String, as type: T.Type) -> T? {
        self[key] as? T
    }
}

let data: [String: Any] = ["n": 3, "s": "x"]
print(data["n", as: Int.self] ?? -1, data["s", as: Int.self] ?? -1)

T задано як Int. Для "n" приведення вдається, для "s" — ні, і спрацьовує ?? -1.

16. Чому тут помилка компіляції?

Swift
struct LicenseKey: ~Copyable {
    let value: String
    consuming func activate() -> String { value }
}

func redeem() {
    let key = LicenseKey(value: "AB-12")
    print(key.activate())
    print(key.activate())
}
redeem()

Noncopyable-значення має одного власника. consuming-метод забирає його, і компілятор не дає використати значення повторно.

17. Що означає <T: ~Copyable> у generic-функції?

Тильда знімає неявну вимогу Copyable. Підходять і копійовані, і noncopyable-типи.

Практика
  1. Напиши func groupCount<T: Hashable>(_ items: [T]) -> [T: Int].
  2. Зроби struct Cache<Key: Hashable, Value> з обмеженням кількості елементів і видаленням найстарішого.
  3. Опиши протокол Repository з асоційованим Entity: Identifiable і зроби generic-клас CachedRepository<Base: Repository>, що обгортає інший репозиторій.
  4. Додай до Array розширення where Element: Numeric з методом runningTotal() -> [Element].
  5. Створи noncopyable-структуру PurchaseToken з consuming func redeem() і переконайся, що компілятор не дає використати токен двічі.
