Макроси

Макроси генерують код під час компіляції. Урок про те, як ними користуватися (freestanding і attached), як вони оголошуються, як розгортаються і як пишеться власний макрос.

У книзі: macros

Що таке макрос

Якщо ти писав source generators у C#, ідея знайома: компілятор запускає твій код, який генерує інший код. Різниця в масштабі. Генератор C# бачить усю компіляцію і додає нові файли. Макрос Swift отримує лише один фрагмент — вираз чи оголошення, до якого застосований, — і повертає код, що вбудовується поруч чи замість виклику.

Що з цього випливає на практиці:

  • макрос не може «тихо» переписати твій код — він тільки доповнює його в місці застосування;
  • результат проходить звичайну перевірку типів, тому помилку в згенерованому коді покаже компілятор;
  • будь-яке розгортання можна відкрити в Xcode (правий клік → Expand Macro) і прочитати як звичайний Swift.
C#

З макросами C/C++ це не має нічого спільного: там текстова підстановка до компіляції, тут перетворення синтаксичного дерева з перевіркою типів.

Є два види: freestanding (самостійні, через #) і attached (прикріплені до оголошення, через @).

Freestanding-макроси

Стоять у коді самостійно — як вираз, інструкція чи оголошення:

Swift
import Foundation
import SwiftUI

// вираз: Predicate будується з типобезпечного замикання на етапі компіляції
let activeTrials = #Predicate<Subscription> { $0.isTrial && $0.daysLeft > 0 }

// оголошення: створює тип для попереднього перегляду в Xcode
#Preview {
    Text("Paywall")
}

// інструкція: попередження компілятора
#warning("Перед релізом прибрати тестові ціни")

Макроси стандартної бібліотеки, які ти вже бачив, — #function, #fileID, #line, #warning, #error.

Attached-макроси

Пишуться через @ перед оголошенням і доповнюють його: додають члени, розширення, атрибути, тіло функції.

Swift
import Observation

@Observable
final class CartModel {
    var items: [String] = []
    var total: Decimal = 0
}

@Observable — це attached-макрос. Він додає до класу сховище спостерігачів, переписує кожну властивість на обчислювану з відстеженням доступу і додає відповідність протоколу Observable. SwiftUI-View, що читає items, перемалюється при зміні саме items.

Інші відомі attached-макроси: @Model (SwiftData), @Test (Swift Testing), @Entry (значення EnvironmentValues). А #expect зі Swift Testing — freestanding-макрос-вираз.

Ролі attached-макросів визначають, що саме вони додають:

Роль Що додає
peer нові оголошення поруч з оригінальним
accessor геттери й сеттери властивості
memberAttribute атрибути до членів типу
member нові члени в тип
extension розширення з протоколами й членами
body тіло функції, яка оголошена без тіла

Один макрос може мати кілька ролей одночасно — як @Observable.

Оголошення макросу

Макрос складається з оголошення (сигнатура й ролі) і реалізації (код, що генерує код). Оголошення виглядає як функція з ключовим словом macro:

Swift
@freestanding(expression)
public macro squared<T: Numeric>(_ value: T) -> T =
    #externalMacro(module: "MyMacrosPlugin", type: "SquaredMacro")

@attached(member, names: named(reset))
public macro Resettable() =
    #externalMacro(module: "MyMacrosPlugin", type: "ResettableMacro")
  • Атрибут перед macro задає вид і роль.
  • names: повідомляє, які імена макрос створить (named(x), prefixed(_), suffixed(Mock), arbitrary). Компілятор має знати це до розгортання.
  • #externalMacro вказує модуль-плагін і тип з реалізацією.
  • Імена freestanding-макросів пишуть у lowerCamelCase (як функції), attached — у UpperCamelCase (як атрибути).
  • Оголошення макросу зазвичай public: макроси існують, щоб їх використовували інші модулі, бо реалізація все одно живе в окремому плагіні.

Розгортання

Коли компілятор зустрічає макрос, він передає його фрагмент коду у вигляді синтаксичного дерева в окремий процес-плагін і вбудовує те, що плагін повернув. Звідси практичні наслідки:

  • Плагін ізольований: він не бачить інших файлів проєкту, не має доступу до диска й мережі. Тому макрос не може, скажімо, прочитати JSON з ресурсів і згенерувати з нього типи.
  • Результат має залежати лише від вхідного коду. Компілятор може кешувати розгортання і перезапускати плагін коли завгодно, тож макрос, що підставляє поточну дату чи випадкове число, працюватиме непередбачувано.
  • Вкладені макроси розгортаються ззовні всередину: спочатку зовнішній, і він може змінити чи прибрати внутрішній ще до його розгортання.
  • Attached-макрос з кількома ролями розгортається окремо для кожної ролі.

Реалізація макросу

Реалізація — Swift-код, що використовує бібліотеку SwiftSyntax для роботи з синтаксичним деревом. Макроси живуть в окремому Swift-пакеті:

swift package init --type macro

Шаблон створює чотири таргети: бібліотеку з оголошеннями (її імпортують клієнти), плагін компілятора з реалізаціями, невелику виконувану програму-клієнт для експериментів і тести.

Спрощена реалізація freestanding-макроса:

Swift
import SwiftSyntax
import SwiftSyntaxMacros
import SwiftCompilerPlugin

// #squared(a + 1)  розгортається в  ((a + 1) * (a + 1))
public struct SquaredMacro: ExpressionMacro {
    public static func expansion(
        of node: some FreestandingMacroExpansionSyntax,
        in context: some MacroExpansionContext
    ) -> ExprSyntax {
        guard let argument = node.arguments.first?.expression else {
            fatalError("потрібен аргумент")
        }
        return "((\(argument)) * (\(argument)))"
    }
}

@main
struct MyMacrosPlugin: CompilerPlugin {
    let providingMacros: [Macro.Type] = [SquaredMacro.self]
}

Для кожної ролі є свій протокол: ExpressionMacro, DeclarationMacro, MemberMacro, PeerMacro, AccessorMacro, ExtensionMacro, BodyMacro тощо.

Розробка й налагодження

  • Макрос — це функція «дерево → дерево», тож його ідеально тестувати юніт-тестами: assertMacroExpansion з SwiftSyntaxMacrosTestSupport порівнює вхідний код з очікуваним розгорнутим.
  • Відлагоджувати реалізацію під час збірки складно, тому основний цикл розробки — через тести.
  • Пакет макросів тягне за собою SwiftSyntax, що помітно збільшує час збірки з нуля.

Додавання макросів у наявний пакет

Якщо макроси потрібні в уже існуючому пакеті, у Package.swift треба:

  • версія інструментів щонайменше 5.9 і import CompilerPluginSupport;
  • залежність від пакета swift-syntax;
  • таргет виду .macro з реалізаціями (залежить від SwiftSyntaxMacros і SwiftCompilerPlugin);
  • звичайний таргет-бібліотека з оголошеннями, що залежить від .macro-таргета;
  • мінімальна версія macOS у platforms, бо плагін виконується на машині розробника.

Замість fatalError реалізація може просто кинути помилку — компілятор покаже її як помилку компіляції в місці виклику макросу.

Порада

Писати власні макроси доводиться рідко. Спочатку навчися читати розгорнутий код чужих макросів (@Observable, @Model) — це допоможе зрозуміти, чому вони поводяться саме так.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що отримує макрос Swift як вхідні дані?

Макрос бачить один вираз чи оголошення і повертає код для вбудовування поруч чи замість виклику.

2. Яке твердження про макроси неправильне?

Макрос лише доповнює код у місці застосування.

3. Що надрукує цей код?

Swift
func greet() {
    print(#function)
}
greet()

#function — макрос стандартної бібліотеки. У функції він дає її ім'я з дужками.

4. Який з цих макросів freestanding?

Freestanding-макроси пишуть через #, attached — через @.

5. Яка роль attached-макросу додає нові члени в тип?

peer додає оголошення поруч, accessor — геттери й сеттери, body — тіло функції.

6. Що робить @Observable з класом?

Тому SwiftUI-View перемальовується лише при зміні властивостей, які він читав.

7. Навіщо в оголошенні attached-макросу вказують names:?

Наприклад, names: named(reset) повідомляє, що з'явиться член reset.

8. Яке твердження про оголошення макросу неправильне?

Attached-макроси називають в UpperCamelCase, як атрибути, а freestanding — у lowerCamelCase.

9. Чому макрос не може прочитати JSON з ресурсів проєкту і згенерувати з нього типи?

Результат має залежати лише від вхідного коду.

10. У якому порядку розгортаються вкладені макроси?

Зовнішній макрос може змінити чи прибрати внутрішній ще до його розгортання.

11. Реалізація #squared повертає "\(argument) * \(argument)" без дужок. На що розгорнеться #squared(a + 1)?

Макрос вставляє синтаксис як є, тож пріоритет операторів зламається. Тому аргумент обгортають у дужки.

12. Який протокол реалізує тип для freestanding-макросу-виразу?

Для кожної ролі свій протокол, а CompilerPlugin лише перелічує макроси плагіна.

13. Як зазвичай перевіряють реалізацію макросу?

Макрос — функція «дерево → дерево», тож тести для нього природні.

14. Якого виду таргет у Package.swift містить реалізацію макросів?

Окрема бібліотека з оголошеннями залежить від цього .macro-таргета.

15. Навіщо пакету з макросами мінімальна версія macOS у platforms, навіть для iOS-застосунку?

Реалізація макросу запускається компілятором, а не на пристрої користувача.

Практика
  1. Створи клас з @Observable і подивись його розгортання в Xcode. Які властивості й члени додав макрос?
  2. Згенеруй шаблон пакета swift package init --type macro і запусти тести, що йдуть у комплекті.
  3. Додай у пакет макрос #squared з цього уроку і тест для нього через assertMacroExpansion. Подумай, чому аргумент обгорнуто в дужки і що буде з #squared(nextRandom()).
  4. Додай діагностику: якщо аргумент — літерал, макрос має видавати попередження.
