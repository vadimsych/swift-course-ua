Базові оператори

Присвоєння, арифметика, порівняння, тернарний оператор, ??, діапазони й логічні оператори. Здебільшого все як у C#, тож урок зосереджений на відмінностях.

У книзі: basicoperators

Термінологія

Оператори бувають унарні (один операнд: -a, !flag), бінарні (a + b) і тернарний (єдиний — a ? b : c). Унарні бувають префіксні (!a) і постфіксні (value!).

Пробіли навколо операторів у Swift мають значення: бінарний оператор пишуть або з пробілами з обох боків, або без них. a+b і a + b працюють, а a +b компілятор прочитає як a і унарний +b.

Присвоєння

= присвоює значення. Кортеж можна розібрати одним присвоєнням:

Swift
var (hp, mana) = (100, 40)

Головна відмінність від C#: присвоєння нічого не повертає. Тому if x = y { } — помилка компіляції, і класичний баг з = замість == неможливий. З тієї ж причини не можна писати ланцюжки a = b = 0.

Арифметика

+, -, *, / працюють як очікується. + також з'єднує рядки.

Ключова відмінність: переповнення — це помилка, а не тихе загортання:

Swift
var counter: Int8 = 127
// counter += 1   // крах у рантаймі: Arithmetic overflow

Якщо загортання потрібне свідомо (хеші, генератори випадкових чисел), є окремі оператори &+, &-, &* — про них в уроці про розширені оператори.

C#

У C# за замовчуванням працює unchecked, і переповнення тихе. У Swift поведінка як у блоці checked { }, тільки завжди і з крахом замість винятку.

Ділення цілих відкидає дробову частину: 7 / 2 == 3. Ділення цілого на нуль — крах, а для Double дає inf або nan.

Остача

% повертає остачу і бере знак від лівого операнда, як у C#:

Swift
17 % 5    // 2
-17 % 5   // -2
17 % -5   // 2 — знак правого операнда ігнорується

Для дробових чисел % не працює. Замість нього truncatingRemainder(dividingBy:):

Swift
let angle = 370.0.truncatingRemainder(dividingBy: 360)  // 10.0

Унарні мінус і плюс

-x змінює знак, +x повертає значення без змін (зустрічається для симетрії в коді).

Складене присвоєння

+=, -=, *=, /=, %= і бітові варіанти. Як і звичайне присвоєння, вони нічого не повертають.

Пастка

У Swift немає ++ і --. Їх прибрали у Swift 3. Пиши i += 1.

Порівняння

==, !=, <, >, <=, >=. Для класів є окремо === і !== — перевірка, що дві змінні вказують на той самий екземпляр (про це в уроці про структури й класи).

Кортежі порівнюються поелементно зліва направо: перший елемент, що відрізняється, вирішує результат. На цьому зручно будувати сортування за кількома ключами — наприклад, таблиця лідерів: спочатку більше перемог, при рівності — менше часу:

Swift
let results = [(name: "Ann", wins: 5, time: 312),
               (name: "Bob", wins: 7, time: 401),
               (name: "Kai", wins: 5, time: 298)]

let table = results.sorted { ( -$0.wins, $0.time) < ( -$1.wins, $1.time) }
// Bob (7), Kai (5, 298), Ann (5, 312)

Обмеження: до шести елементів, і кожен елемент має підтримувати оператор. Кортеж із Bool через < не порівняти, бо Bool не Comparable.

Тернарний оператор

умова ? a : b — як у C#. Але в Swift if і switch теж можуть бути виразами (урок про керування потоком), тож для чогось складнішого за одну умову краще вони:

Swift
let label = hp > 0 ? "живий" : "переможений"

Оператор ??

a ?? b розгортає опціонал a або повертає b. Права частина обчислюється, тільки якщо a дорівнює nil (ліниво, через autoclosure):

Swift
let saved: String? = nil
let name = saved ?? loadDefaultName()   // loadDefaultName викличеться лише при nil

Тип b має збігатися з типом усередині опціоналу, або b сам може бути опціоналом, і тоді результат — опціонал. Ланцюжки a ?? b ?? c дозволені.

Діапазони

Тут у Swift більше можливостей, ніж у C#.

Swift
for i in 1...5 { }       // замкнений: 1, 2, 3, 4, 5
for i in 0..<5 { }       // напіввідкритий: 0, 1, 2, 3, 4

let laps = [61.2, 59.8, 60.4, 58.9, 59.1, 60.0]
laps[3...]               // з четвертого кола до кінця
laps[...1]               // перші два кола включно
laps[..<4]               // перші чотири кола
let empty = 4..<4        // порожній діапазон: a..<a не містить жодного значення

let teen = 13...19
teen.contains(15)        // true
  • a...b — замкнений діапазон, включає обидва кінці. Потребує a <= b, інакше крах.
  • a..<b — напіввідкритий, без b. Ідеальний для індексів: 0..<array.count.
  • Односторонні a..., ...b, ..<b — коли одна межа очевидна з контексту. Одностороннім діапазоном з відкритим початком не можна ітерувати (звідки почати?), а з відкритим кінцем можна, але треба самому зупинити цикл.
C#

C# 8 має .. і ^ для індексів (arr[2..], arr[^1]). У Swift немає «індексу з кінця» (^1), замість цього items.last або items[items.count - 1]. System.Range у C# теж можна зберігати й передавати, але він описує лише індекси. Діапазони Swift — generic-типи (Range<Bound>, ClosedRange<Bound>) з будь-якими порівнюваними межами: числами, датами, рядками, з contains, ітерацією й використанням у switch.

Логічні оператори

!, &&, || працюють лише з Bool і обчислюються за короткою схемою — як у C#. Пріоритет && вищий за ||, і на цьому легко помилитися. Ось реальний баг з пейвола:

Swift
let isSubscribed = false
let hasTrial = true
let isReviewer = true      // App Review бачить окремий екран

// Задум: «показати преміум, якщо є підписка або тріал — але не рев'юеру»
if isSubscribed || hasTrial && !isReviewer {
    showPremium()          // компілятор читає як isSubscribed || (hasTrial && !isReviewer)
}

Якщо рев'юер має підписку, умова однаково дасть true: !isReviewer застосовується лише до тріалу, а не до всієї умови. Правильно — розставити дужки під свій задум:

Swift
if (isSubscribed || hasTrial) && !isReviewer {
    showPremium()
}

Правило: коли в умові змішано && і ||, став дужки завжди — навіть якщо пріоритети дають потрібний результат. Читач коду не мусить пам'ятати таблицю пріоритетів.

Практика
  1. Відсортуй масив кортежів (level: Int, name: String) спочатку за рівнем за спаданням, потім за іменем — однією умовою з порівнянням кортежів.
  2. Виведи кожен третій елемент масиву, використовуючи stride(from:to:by:) і порівняй з 0..<count.
  3. Перевір, що станеться з let r = 5...1. Чому саме так?
  4. Напиши функцію clamp(_ value: Int, to range: ClosedRange<Int>) -> Int.
