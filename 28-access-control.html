Контроль доступу

Шість рівнів доступу Swift, модулі й пакети, правила за замовчуванням, private(set), доступ у тестах і як рівні доступу взаємодіють з типами, протоколами, розширеннями й узагальненнями.

У книзі: accesscontrol

Модулі, файли й пакети

Контроль доступу в Swift будується навколо трьох одиниць:

  • Модуль — одиниця розповсюдження коду: застосунок, фреймворк, бібліотека, Swift-пакет-таргет. Імпортується через import.
  • Файл — окремий .swift-файл усередині модуля.
  • Пакет — група модулів, що збираються разом: таргети одного Swift Package (Package.swift) або, у Xcode, таргети з однаковим налаштуванням Package Access Identifier.
C#

Модуль ≈ assembly, і internal в обох мовах означає «в межах збірки». Нового тут два рівні: fileprivate (видно в межах файлу) і package (видно в межах пакета).

Рівні доступу

Від найвідкритішого до найзакритішого:

Рівень Де доступно
open будь-де; клас можна успадковувати, а члени перевизначати в інших модулях
public будь-де; але успадковувати й перевизначати — лише в модулі, де оголошено
package у всіх модулях того самого пакета
internal у межах модуля (за замовчуванням)
fileprivate у межах файлу
private у межах оголошення та його розширень у тому самому файлі

open застосовується лише до класів і їхніх членів. Різниця між open і public — свідоме рішення автора бібліотеки: чи дозволено клієнтам успадковуватися.

Головний принцип

Правило одне: жодна сутність не може «показати назовні» те, що саме закрите сильніше за неї. Якщо клієнт бачить функцію, він мусить бачити й типи, з якими вона працює. Тому:

  • публічна властивість не може мати внутрішній (internal) тип;
  • функція, сабскрипт чи ініціалізатор не можуть бути відкритішими за типи своїх параметрів і результату.

Рівні за замовчуванням

Майже все за замовчуванням internal. Тому в застосунку з одного модуля писати модифікатори доступу майже не потрібно.

Застосунки з одного таргета

Увесь код і так у межах модуля, тож internal достатньо. Корисно лише приховувати деталі реалізації через private і fileprivate.

Фреймворки

Публічний API фреймворку позначають public або open. Усе інше лишається internal і є деталлю реалізації, яку можна змінювати без зламу клієнтів.

Таргети юніт-тестів

Модуль, скомпільований з увімкненим testing (у Debug за замовчуванням), можна імпортувати з атрибутом @testable, і тоді тести бачать його internal-сутності:

Swift
@testable import PaywallKit

Синтаксис

Swift
public class AnalyticsClient { }
internal struct EventQueue { }        // internal можна не писати
fileprivate func formatPayload() { }
private let apiKey = "..."

public final class Tracker {
    public var isEnabled = true
    var batchSize = 20                 // internal
    private var buffer: [String] = []
    public init() {}
}

Власні типи

Рівень доступу типу впливає на рівень за замовчуванням його членів:

  • для private типу члени за замовчуванням private, а для fileprivate — fileprivate (на практиці члени обох видимі в межах файлу);
  • для internal чи public типу члени за замовчуванням internal.

Тобто public-тип не робить свої члени публічними автоматично. Кожен член публічного API позначають явно — це захищає від випадкового експорту.

Swift
public struct Receipt {
    public let id: String          // явно публічне
    let rawData: Data              // internal — клієнти не бачать
    public init(id: String) { self.id = id; rawData = Data() }
}

Кортежі

Рівень доступу кортежу — найнижчий з рівнів його елементів. Явно його не вказують.

Функціональні типи

Рівень доступу функції обчислюється як найнижчий серед типів параметрів і результату. Якщо він нижчий за контекст, функцію треба явно позначити цим рівнем:

Swift
private struct Secret { }

// func makeSecret() -> Secret { Secret() }       // помилка: функція internal, тип private
private func makeSecret() -> Secret { Secret() }  // ок

Перелічення

Варіанти enum мають той самий рівень доступу, що й сам enum; задати окремий рівень окремому варіанту не можна.

Сирі й асоційовані значення

Типи сирих і асоційованих значень мусять бути щонайменше такими ж відкритими, як enum.

Вкладені типи

Вкладений тип отримує рівень зовнішнього, але не вище internal: у public-типі вкладений тип за замовчуванням internal. Щоб він був публічним, пиши public явно.

Підкласи

Правила наслідування залежать від модуля:

  • у своєму модулі можна успадковувати будь-який доступний клас і перевизначати будь-який видимий член;
  • з іншого модуля — лише open-класи й open-члени. public дає їх використовувати, але не успадковувати.

Підклас не може бути відкритішим за суперклас. А перевизначений член може бути відкритішим, ніж у суперкласі — так можна відкрити підкласам частину API, яку суперклас ховав:

Swift
open class AnalyticsScreen {
    var screenName: String { "unknown" }      // internal
}

public final class PaywallScreen: AnalyticsScreen {
    public override var screenName: String { "paywall" }   // підвищили до public
}

Константи, змінні, властивості й сабскрипти

Не можуть бути відкритішими за свій тип. public var x: InternalType — помилка. Сабскрипт так само не може бути відкритішим за типи індексу й результату.

Геттери й сеттери

Сеттер можна зробити менш доступним, ніж геттер, через private(set), fileprivate(set), internal(set), package(set):

Swift
public struct Wallet {
    public private(set) var coins = 0      // читати можуть усі, змінювати — лише Wallet

    public mutating func earn(_ n: Int) {
        coins += n
    }
}

Це одна з найчастіше вживаних конструкцій у Swift: зовнішній код бачить стан, але змінює його лише через методи.

C#

Те саме, що public int Coins { get; private set; }.

Ініціалізатори

Власний ініціалізатор може мати рівень, не вищий за свій тип, а типи його параметрів не можуть бути закритішими за сам ініціалізатор. required-ініціалізатор має той самий рівень, що й клас.

Ініціалізатори за замовчуванням

Автоматичний init() має той самий рівень, що й тип, але не вище internal. Для public-типу, який має бути створюваним ззовні модуля, публічний init() треба написати явно.

Memberwise-ініціалізатори

Memberwise-ініціалізатор структури — private, якщо хоча б одна збережена властивість private; fileprivate, якщо є fileprivate; інакше internal. Публічним він ніколи не буває автоматично — для публічних структур бібліотек ініціалізатор пишуть вручну.

Пастка

Класична помилка при винесенні коду в Swift Package: структура стала public, а створити її з застосунку не вдається — бо memberwise-ініціалізатор лишився internal.

Протоколи

Рівень доступу протоколу визначає, хто його бачить. Вимоги протоколу автоматично мають той самий рівень, що й протокол, і окремо задати їм рівень не можна.

Успадкування протоколів

Протокол-нащадок не може бути відкритішим за батьківський.

Відповідність протоколам

Відповідність протоколу глобальна: тип не може відповідати одному протоколу двома різними способами в різних місцях програми. Тип може відповідати протоколу з нижчим рівнем доступу, але сама відповідність діє на рівні, мінімальному з двох. Реалізації вимог мусять бути щонайменше такими ж доступними, як відповідність:

Swift
public protocol Resettable {
    func reset()
}

public struct Timer: Resettable {
    public func reset() { }   // має бути public, бо і тип, і протокол public
}

Розширення

Члени, додані в розширенні, мають за замовчуванням той самий рівень, що й члени в оригінальному типі. Можна задати рівень для всього розширення: private extension Foo { ... }. Для розширення з відповідністю протоколу рівень явно не вказують — він визначається протоколом.

Приватні члени в розширеннях

private-члени видно в оригінальному оголошенні й у всіх його розширеннях у тому самому файлі — у будь-якому напрямку:

Swift
struct Checkout {
    private var items: [String] = []
    func summary() -> String { "\(items.count) товарів, знижка \(discountPercent)%" }  // бачить private з розширення
}

extension Checkout {
    private var discountPercent: Int { items.count >= 3 ? 10 : 0 }   // оголошено в розширенні
}

extension Checkout {
    mutating func add(_ item: String) {
        items.append(item)               // private з оголошення
        _ = discountPercent              // і private з іншого розширення
    }
}

Тому код можна розбивати на розширення за відповідальністю, не відкриваючи приватний стан.

Узагальнення

Рівень доступу generic-типу чи функції — мінімальний з рівня самого оголошення і рівнів обмежень його параметрів типу.

Псевдоніми типів

Для контролю доступу псевдонім вважається окремим типом: він не може бути відкритішим за тип, на який посилається (public typealias X = InternalType — помилка). Те саме стосується псевдонімів, що задають асоційовані типи протоколів.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що таке пакет з погляду контролю доступу?

Пакет об'єднує кілька модулів. Рівень package робить сутність видимою в усіх модулях того самого пакета.

2. Чим open відрізняється від public?

open застосовується лише до класів і їхніх членів і свідомо дозволяє клієнтам успадковуватися.

3. Який рівень доступу Swift застосовує, якщо модифікатор не вказано?

Майже все за замовчуванням internal, тому в застосунку з одного модуля модифікатори пишуть рідко.

4. Що дає @testable import MyModule у таргеті тестів?

Модуль, скомпільований з увімкненим testing, можна імпортувати як @testable, і тоді його internal-сутності доступні тестам.

5. У public final class Tracker оголошено var batchSize = 20 без модифікатора. Який рівень доступу має batchSize?

Без модифікатора член отримує internal. Публічний тип не робить члени публічними автоматично.

6. Чому тут помилка компіляції?

Swift
private struct Secret {}

func makeSecret() -> Secret { Secret() }

Рівень функції не може бути вищим за типи її параметрів і результату. Тут потрібно private func makeSecret().

7. Яке твердження неправильне?

Задати окремий рівень доступу варіанту enum не можна — він завжди такий самий, як у enum.

8. Яке твердження про підкласи правильне?

Перевизначення дозволяє підвищити рівень члена, наприклад з internal до public. А підклас не може бути відкритішим за суперклас.

9. Чому тут помилка компіляції?

Swift
struct Token {}

public struct Session {
    public var token: Token
}

Жодна сутність не може показати назовні те, що закрите сильніше за неї. Клієнт, який бачить token, мусить бачити й тип Token.

10. Чому тут помилка компіляції?

Swift
public struct Wallet {
    public private(set) var coins = 0
    public mutating func earn(_ n: Int) { coins += n }
}

func run() {
    var w = Wallet()
    w.earn(5)
    w.coins = 100
    print(w.coins)
}
run()

public private(set) дозволяє всім читати значення, а змінювати — лише самому типу.

11. Яке твердження неправильне?

Memberwise-ініціалізатор ніколи не буває публічним автоматично. Для публічних структур бібліотек його пишуть вручну.

12. Чому тут помилка компіляції?

Swift
public protocol Resettable {
    func reset()
}

public struct Timer: Resettable {
    func reset() {}
}

Реалізації вимог мусять бути щонайменше такими ж доступними, як відповідність. Тут відповідність public, а метод — internal.

13. Що надрукує цей код?

Swift
struct Cart {
    private var items: [String] = []
    func summary() -> String { "\(items.count) товари, знижка \(discount)%" }
}

extension Cart {
    private var discount: Int { items.count >= 3 ? 10 : 0 }
}

extension Cart {
    mutating func add(_ item: String) { items.append(item) }
}

func run() {
    var cart = Cart()
    cart.add("a"); cart.add("b"); cart.add("c")
    print(cart.summary())
}
run()

private-члени видно в оголошенні й у всіх його розширеннях у тому самому файлі, у будь-якому напрямку.

14. Як визначається рівень доступу generic-функції?

Generic-оголошення не може бути відкритішим за протоколи й типи, якими обмежено його параметри типу.

15. Чому тут помилка компіляції?

Swift
struct Config {}

public typealias AppConfig = Config

Для контролю доступу псевдонім вважається окремим типом. public-псевдонім на internal-тип заборонено.

Практика
  1. Створи Swift Package з двома таргетами (Core і Feature) і познач кілька API як package, щоб вони були видні між таргетами, але не клієнтам пакета.
  2. Зроби публічну структуру Price і переконайся, що з іншого модуля її не можна створити без явного public init.
  3. Познач властивість public private(set) і спробуй змінити її ззовні.
  4. Напиши тест з @testable import для internal-функції.
