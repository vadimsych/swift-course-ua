Мова крок за кроком · урок 01

Основи

Константи й змінні, числові типи, виведення типів, кортежі, опціонали, базово про помилки й безпеку пам'яті, а також assertions і preconditions.

У книзі: thebasics

Константи й змінні

let оголошує константу, var — змінну. У Swift заведено писати let усюди, де значення не змінюється, і компілятор сам підкаже, якщо var ніколи не модифікується.

Swift
let levelCount = 12
var currentLevel = 1
currentLevel += 1

var wins = 0, losses = 0, draws = 0   // кілька в одному рядку

Значення константи не обов'язково відоме під час компіляції, і його можна присвоїти пізніше, але рівно один раз на кожному шляху виконання:

Swift
let reward: Int
if currentLevel > 10 {
    reward = 500
} else {
    reward = 100
}
// reward = 0  // помилка: константу вже ініціалізовано
C#

let — це не const (той лише для compile-time значень) і не зовсім readonly. Ближче за все — локальна змінна, якій можна присвоїти один раз. Для let-властивості класу посилання незмінне, а об'єкт усередині змінювати можна, як у readonly поля в C#. А от let зі структурою робить незмінною всю структуру — про це в уроці про структури.

Анотації типу

Тип пишеться після імені через двокрапку. Потрібен він, коли початкового значення немає або коли треба інший тип, ніж вивів би компілятор:

Swift
var playerName: String
let volume: Float = 1     // без анотації було б Int
var minPrice, maxPrice: Double

Імена

Імена можуть містити майже будь-які Unicode-символи, зокрема кирилицю й емодзі, але не пробіли, математичні символи, стрілки й не можуть починатися з цифри. На практиці пишуть латиницею в lowerCamelCase для змінних і функцій та UpperCamelCase для типів.

Якщо дуже потрібно використати ключове слово як ім'я, його беруть у зворотні лапки:

Swift
let `default` = "fallback"
Swift 6

Зворотні лапки тепер дозволяють і «сирі ідентифікатори» з пробілами та цифрами на початку, наприклад для назв тестів: func `login fails with wrong password`(). Детальніше в уроці про лексичну структуру.

Виведення

print(_:separator:terminator:) виводить значення. Інтерполяція рядків — через \(...):

Swift
let coins = 250
print("Монет: \(coins)")              // як $"Монет: {coins}"
print("a", "b", "c", separator: "-")  // a-b-c

Коментарі й крапки з комою

Коментарі як у C#: // і /* */. Різниця в тому, що багаторядкові коментарі вкладаються: /* зовнішній /* внутрішній */ все ще коментар */. Тому закоментувати шматок коду, у якому вже є /* */, безпечно.

Документаційні коментарі пишуть через /// у форматі Markdown (а не XML, як у C#):

Swift
/// Повертає кількість досвіду за рівень.
/// - Parameter level: Номер рівня, починаючи з 1.
/// - Returns: Кількість XP.
func xp(for level: Int) -> Int { level * 100 }

Крапка з комою потрібна лише тоді, коли кілька інструкцій пишуть в одному рядку: let a = 1; print(a).

Цілі числа

Є знакові Int8, Int16, Int32, Int64 і беззнакові UInt8 … UInt64. Межі доступні через .min і .max:

Swift
let maxByte = UInt8.max   // 255
let minShort = Int16.min  // -32768

Int має розмір машинного слова платформи: на iPhone, iPad і Mac це 64 біти (Int64), а на 32-бітних платформах, наприклад частині моделей Apple Watch, — 32 біти. Так само UInt. Використовуй Int для всіх цілих чисел за замовчуванням, навіть якщо значення завжди невід'ємне. Це робить код сумісним і позбавляє від перетворень.

UInt використовують тільки тоді, коли справді потрібен беззнаковий тип машинного розміру. Наприклад, Array.count має тип Int, а не UInt.

C#

У C# int завжди 32-бітний, а long — 64. У Swift базовий Int на 64-бітних платформах відповідає long. І ще: byte у C# беззнаковий, а аналог у Swift — UInt8, тоді як Int8 відповідає sbyte.

Числа з рухомою комою

Double — 64-бітне число (близько 15 значущих цифр), Float — 32-бітне (близько 6 цифр). За замовчуванням дробовий літерал стає Double. Є ще Float16 для специфічних задач (ML, графіка), а також псевдоніми Float32 і Float64.

Дробові числа зберігаються у двійковому форматі IEEE 754, тому значення округлюється до найближчого представимого: 0.1 + 0.2 == 0.3 — false. Чим більше число, тим більший крок між сусідніми представимими значеннями. Є й особливі значення: .infinity, -.infinity, .nan (x.isNaN) і від'ємний нуль -0.0, який дорівнює 0.0.

Коли що брати:

  • Цілі числа — для лічильників, індексів, кількостей і всього, що за природою дискретне. А також для грошей у мінімальних одиницях (копійках, центах), щоб уникнути похибок округлення.
  • Double — для вимірювань, фізики, координат, будь-яких неточних величин.
  • Float — тільки коли API вимагає саме його або критична пам'ять (великі масиви для GPU).
Пастка

У Unity ти звик до float усюди: Vector3, Time.deltaTime. В iOS-API все навпаки: CGFloat (на 64-біт фактично Double), TimeInterval (це Double). Тут Double — норма.

Безпека типів і виведення типів

Swift строго типізований: не можна передати String туди, де очікується Int. Але тип майже завжди виводиться з контексту, тому код рідко містить явні анотації:

Swift
let lives = 3          // Int
let speed = 4.5        // Double
let total = 3 + 0.25   // Double: літерали без типу підлаштовуються

Числові літерали

Swift
let decimal = 42
let binary = 0b101010
let octal = 0o52
let hex = 0x2A

let big = 1_000_000          // підкреслення для читабельності
let precise = 1.25e3         // 1250.0
let hexFloat = 0x1p4         // 16.0 — двійковий порядок p обов'язковий
// let bad = .5              // помилка: у Swift цифри мають бути з обох боків крапки
let leading = 007_250.5      // нулі на початку дозволені й ігноруються

Перетворення числових типів

Жодних неявних перетворень між числовими типами. Навіть Int8 в Int треба перетворити явно. Значення, що не вміщається, — помилка компіляції для літералів і крах під час виконання для змінних:

Swift
let small: UInt8 = 200
let large: Int = 1_000
let sum = large + Int(small)        // явне розширення

// let overflow: Int8 = 200        // помилка компіляції: не вміщається
// let crash = UInt8(large)         // крах у рантаймі: не вміщається
let safe = UInt8(exactly: large)    // nil замість краху
let clamped = UInt8(clamping: large) // 255

Між цілими й дробовими так само:

Swift
let itemsInCart = 3
let pricePerItem = 49.99
let total = Double(itemsInCart) * pricePerItem   // 149.97
let wholeHryvnias = Int(total)                   // 149 — дробова частина відкидається
let rounded = Int(total.rounded())               // 150
let cents = Int((total * 100).rounded())         // 14997
C#

У C# int неявно стає long чи double. У Swift ні. Спочатку дратує, потім рятує від тихих втрат точності. Літерали ж типу не мають, тому let d: Double = 3 працює без перетворення.

Псевдоніми типів

typealias дає існуючому типу інше ім'я, як using Alias = Type; у C#:

Swift
typealias PlayerID = UInt64
typealias Completion = (Result<String, Error>) -> Void

let id: PlayerID = 42

Це саме псевдонім, а не новий тип: PlayerID і UInt64 повністю взаємозамінні.

Булеві значення

Тип Bool зі значеннями true і false. В умовах дозволено лише Bool: if count { } не скомпілюється, треба if count != 0 { }. Корисні методи: isMuted.toggle(), а також .random().

Кортежі

Кортеж — анонімна група значень, найчастіше як результат функції, коли заводити окрему структуру зарано:

Swift
func parseVersion(_ s: String) -> (major: Int, minor: Int)? {
    let parts = s.split(separator: ".").compactMap { Int($0) }
    guard parts.count >= 2 else { return nil }
    return (parts[0], parts[1])
}

if let v = parseVersion("6.4") {
    print(v.major, v.minor)                  // за іменами елементів
    print(v.0)                               // або за номером
}

let (major, _) = parseVersion("5.10") ?? (0, 0)   // розбір з відкиданням зайвого

Імена елементів — частина типу кортежу, але необов'язкова. Для довгоживучих даних і публічного API краще завести struct.

C#

Те саме, що кортежі (int major, int minor) у C#, і синтаксис майже однаковий.

Опціонали

Опціонал описує значення, якого може не бути. String? означає «або String, або nil». Будь-який тип без ? гарантовано має значення.

Опціонали з'являються скрізь, де результат не гарантований:

Swift
let settings = ["theme": "dark"]
let fontSize = settings["fontSize"]          // String? — ключа може не бути
let firstVIP = users.first { $0.isVIP }       // User? — такого може не знайтись
let url = URL(string: userInput)             // URL? — рядок може бути некоректним

nil

nil можна присвоїти тільки опціоналу. Змінна-опціонал без значення автоматично стає nil:

Swift
var lastError: String?   // nil за замовчуванням
C#

Схоже на nullable reference types, але з принциповою різницею: у Swift це не попередження, а частина типу. String і String? — різні типи, і без розгортання ти не викличеш метод на опціоналі. Плюс опціонали працюють однаково для value і reference типів: Int? і Enemy? поводяться ідентично.

Прив'язування опціоналу

Щоб працювати зі значенням, його спочатку «розгортають». Основний інструмент — if let і guard let:

Swift
if let theme = settings["theme"] {
    apply(theme)                      // theme тут — String, і живе лише в цьому блоці
} else {
    apply("system")
}

if let theme = settings["theme"], let accent = settings["accent"], theme == "dark" {
    applyDark(accent: accent)         // кілька умов через кому — усі мають виконатися
}

var nickname: String? = loadNickname()
if let nickname {                     // коротка форма: те саме ім'я
    print("Привіт, \(nickname)")
}

if var draft = savedDraft {           // if var — змінна копія для модифікації
    draft += " (чернетка)"
    show(draft)
}

while let job = pendingJobs.popLast() {   // прив'язування працює й у while
    run(job)
}

guard let робить те саме, але розгорнуте значення доступне після інструкції, а гілка else мусить вийти з поточної області:

Swift
func open(_ link: String?) {
    guard let link, let url = URL(string: link) else {
        print("Немає посилання")
        return
    }
    print("Відкриваємо \(url)")      // url доступний до кінця функції
}

Значення за замовчуванням

Оператор ?? працює як у C#:

Swift
let title = nickname ?? "Гравець"

Примусове розгортання

value! дістає значення без перевірки, а на nil зупиняє програму. Тобто це не «я впевнений», а «якщо я помилився — нехай падає»:

Swift
let privacyURL = URL(string: "https://example.com/privacy")!   // літерал у коді: nil означав би баг

Неявно розгорнуті опціонали

Тип T! — опціонал, який компілятор сам розгортає там, де потрібне не-опціональне значення. Він існує для однієї ситуації: значення гарантовано з'явиться одразу після створення об'єкта, але не в самому init. Класичний приклад — outlet в UIKit, який заповнює система після завантаження сторіборду:

Swift
final class PaywallController: UIViewController {
    @IBOutlet var titleLabel: UILabel!

    override func viewDidLoad() {
        super.viewDidLoad()
        titleLabel.text = "Pro"          // розгорнуто автоматично
        let label = titleLabel           // а тут тип — UILabel?, бо контекст допускає опціонал
    }
}

Правило виведення: якщо результат можна залишити опціональним, компілятор так і робить; розгортання відбувається лише там, де без нього не скомпілюється. З T! можна працювати і як зі звичайним опціоналом (if let, != nil). Звернення, поки значення nil, — крах. У SwiftUI-коді такі опціонали майже не трапляються.

Пастка

Звичка з C# писати ! (null-forgiving operator) тут небезпечна. У C# ! лише вимикає попередження, а в Swift це реальна перевірка в рантаймі з крахом застосунку.

Безпека пам'яті

Swift за замовчуванням не дає зробити низку помилок, які в C чи небезпечному C# призводять до невизначеної поведінки:

  • читання змінної до ініціалізації;
  • вихід за межі масиву (крах замість читання чужої пам'яті);
  • переповнення цілого числа (крах замість тихого загортання);
  • звернення до звільненого об'єкта;
  • конфліктний одночасний доступ до тієї самої пам'яті (див. урок про безпеку пам'яті);
  • data races між потоками (у режимі Swift 6, див. урок про конкурентність).

Коли перевірки в рантаймі знаходять порушення, програма зупиняється, а не продовжує роботу з пошкодженими даними. Обійти захист можна лише явно позначеними засобами: типами й функціями зі словами unsafe, unchecked, unmanaged у назві (UnsafePointer, Unmanaged, @unchecked Sendable, unowned(unsafe)), або режимом компіляції -Ounchecked.

Обробка помилок

Функція, що може завершитися помилкою, позначається throws, а виклик — try. Ловлять помилки в do-catch:

Swift
enum SaveError: Error {
    case diskFull
}

func save() throws {
    throw SaveError.diskFull
}

do {
    try save()
} catch {
    print("Не вдалося зберегти: \(error)")
}

Головна відмінність від C#: те, що функція кидає помилку, видно в її сигнатурі, а кожен виклик явно позначений try. Детально — в уроці про обробку помилок.

Assertions і preconditions

Це перевірки інваріантів під час виконання. Якщо умова хибна, виконання зупиняється.

Swift
let volume = settings.volume
assert((0...1).contains(volume), "Гучність має бути в межах 0…1, а не \(volume)")

func item(at index: Int, in items: [String]) -> String {
    precondition(items.indices.contains(index), "Індекс \(index) поза межами")
    return items[index]
}

func handle(_ state: Int) {
    switch state {
    case 0, 1: break
    default: assertionFailure("Невідомий стан \(state)")
    }
}

Різниця в тому, де вони працюють:

Функція Debug Release (-O) -Ounchecked
assert, assertionFailure перевіряє ігнорується ігнорується
precondition, preconditionFailure перевіряє перевіряє компілятор вважає умову істинною
fatalError зупиняє зупиняє зупиняє
  • assert — для перевірок під час розробки, які не повинні гальмувати релізну збірку.
  • precondition — для умов, порушення яких робить подальшу роботу безглуздою, навіть у релізі.
  • fatalError("…") — для коду, який не повинен виконатися ніколи, наприклад обов'язковий init(coder:), який ти не підтримуєш.
C#

assert ≈ Debug.Assert. precondition — як throw new InvalidOperationException(), тільки без можливості перехопити: програма просто зупиняється. Assertions — не механізм обробки помилок, а спосіб рано знайти баг.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що станеться з цим кодом?

Swift
let reward: Int
reward = 100
reward = 200

let можна оголосити без значення й присвоїти пізніше, але рівно один раз. Друге присвоєння — помилка компіляції.

2. Що надрукує цей код?

Swift
let total = 3 + 0.5
print(type(of: total))

Літерали самі по собі не мають типу і підлаштовуються один під одного. Дробовий літерал за замовчуванням — Double. А от дві змінні Int і Double без перетворення скласти не вийде.

3. Є let count: Int = 7 і let price: Double = 2.5. Як правильно отримати Double-добуток?

Неявних перетворень між числовими типами в Swift немає. Значення перетворюють, створюючи новий: Double(count).

4. Що надрукує цей код?

Swift
let saved: String? = nil
print(saved ?? "guest")

?? повертає значення опціоналу або, якщо там nil, значення праворуч — як у C#.

5. Чим guard let відрізняється від if let?

if let дає значення лише всередині блоку. guard let — для раннього виходу: якщо значення немає, виходимо, а далі працюємо з уже розгорнутим.

6. Що робить value!, якщо value дорівнює nil?

! у Swift — справжня перевірка під час виконання. На відміну від null-forgiving ! у C#, при nil застосунок падає.

Практика
  1. Напиши функцію parseAge(_ text: String) -> Int?, яка повертає вік, якщо рядок — число від 0 до 150, інакше nil.
  2. Використай її з if let, guard let і ??.
  3. Оголоси let score: UInt8 = 250 і спробуй додати до нього 10. Що станеться? Тепер спробуй UInt8(clamping: 260) і UInt8(exactly: 260).
  4. Поверни з функції кортеж (min: Int, max: Int)? для масиву цілих (і nil для порожнього масиву).
