Приведення типів

Перевірка типу через is, приведення вниз через as? і as!, підняття через as, робота з Any і AnyObject — і чому в Swift до приведення типів вдаються рідше, ніж у C#.

У книзі: typecasting

Коли це потрібно

Приведення типів потрібне, коли статичний тип значення загальніший за реальний: елемент масиву базового класу, значення з Any, протокольний тип. Типовий iOS-приклад — обійти ієрархію view й знайти конкретні елементи:

Swift
import UIKit

@MainActor
func allTextFields(in root: UIView) -> [UITextField] {
    var result: [UITextField] = []
    for sub in root.subviews {
        if let field = sub as? UITextField {       // умовне приведення вниз
            result.append(field)
        }
        result += allTextFields(in: sub)           // рекурсія по дереву
    }
    return result
}

subviews має тип [UIView], а реальні елементи — підкласи: UILabel, UIButton, UITextField. Приведення нічого не змінює в самому об'єкті: це лише інший «погляд» на той самий екземпляр.

Три оператори

Оператор Що робить Аналог у C#
x is T true, якщо в рантаймі x — це T або його підтип x is T
x as? T повертає T?: значення або nil x as T
x as! T повертає T або падає (T)x, але крах замість InvalidCastException
x as T гарантоване приведення, перевірене компілятором неявне приведення
Swift
let views: [UIView] = [UILabel(), UIButton(), UISwitch()]

let interactiveCount = views.filter { $0 is UIControl }.count   // 2: кнопка й перемикач

if let label = views.first as? UILabel {
    label.text = "Готово"
}

let button = views[1] as! UIButton   // впевнені — інакше крах

as без знаків застосовують для підняття до суперкласу чи протоколу, мостових перетворень (String ↔ NSString) і щоб уточнити тип літерала: let ratio = 1 as Double.

Порада

as! прийнятний лише там, де невдача — це баг у коді, наприклад tableView.dequeueReusableCell(withIdentifier:) as! ProductCell, коли комірку зареєстровано саме цього класу.

Приведення в switch

Кілька варіантів типу зручніше розібрати в switch:

Swift
@MainActor
func describe(_ control: UIView) -> String {
    switch control {
    case let toggle as UISwitch:
        "перемикач: \(toggle.isOn ? "увімк." : "вимк.")"
    case let button as UIButton where button.isEnabled:
        "активна кнопка"
    case is UIButton:
        "вимкнена кнопка"
    default:
        "інший елемент"
    }
}

case let x as T — приведення з прив'язуванням, case is T — лише перевірка.

Any і AnyObject

  • Any — значення будь-якого типу: структури, enum, класу, кортежу, функції, опціоналу.
  • AnyObject — екземпляр будь-якого класу.

Найчастіше Any трапляється на межі з динамічними API: userInfo сповіщень, параметри аналітики, JSONSerialization. Розбирати його зручно тим самим switch:

Swift
import Foundation

func describe(_ value: Any) -> String {
    switch value {
    case let s as String:
        return "рядок «\(s)»"
    case let n as Int where n < 0:
        return "від'ємне ціле \(n)"
    case let n as Int:
        return "ціле \(n)"
    case let x as Double:
        return "дробове \(x)"
    case let list as [Any]:
        return "масив з \(list.count) елементів"
    case let object as [String: Any]:
        return "об'єкт з ключами \(object.keys.sorted())"
    case is NSNull:
        return "null"
    default:
        return "невідомий тип \(type(of: value))"
    }
}

Так само можна приводити до кортежів і функціональних типів (as? (Int, Int), as? () -> Void), а також до протоколів: value as? any CustomStringConvertible, value is any Error.

Пастка

Числа з JSONSerialization приходять як NSNumber, а NSNumber успішно приводиться і до Int, і до Bool: JSON-число 1 пройде as? Bool, а true — as? Int. Надійно розрізнити їх через приведення не вийде. Не розбирай JSON вручну — використовуй Codable.

Пастка

Якщо покласти опціонал в Any, компілятор попередить: значення «зникає» в коробці разом з можливим nil, і потім легко забути його перевірити. Якщо так і задумано, пиши явно optionalValue as Any.

Порада

Any — крайній засіб. У власному коді краще протокол або enum з асоційованими значеннями: компілятор перевірить вичерпність, і default не «проковтне» невідомий випадок.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що повертає view as? UIButton?

as? — умовне приведення, аналог as у C#.

2. Що станеться, якщо as! не вдасться?

as! — примусове приведення. У C# прямий каст кинув би InvalidCastException, а в Swift — крах.

3. Що перевіряє x is UIControl?

is повертає true і для підкласів: кнопка й перемикач — теж UIControl.

4. Яке твердження неправильне?

NSNumber приводиться і до Bool, і до Int, тож розрізнити їх через as? не вийде. Для JSON краще Codable.

Практика
  1. Напиши функцію, що знаходить у дереві view першу кнопку з певним accessibilityIdentifier.
  2. Порахуй у масиві [Any] кількість рядків, чисел і всього іншого через switch.
  3. Розбери userInfo: [AnyHashable: Any] сповіщення про покупку у власну структуру через as?.
  4. Заміни масив [Any] з пункту 2 на enum Value з асоційованими значеннями і порівняй, як змінився код обробки.
