Успадкування

Базові класи, підкласи, перевизначення методів, властивостей і спостерігачів, звернення до super і заборона перевизначення через final.

У книзі: inheritance

Базовий клас

Успадковувати можуть лише класи. Клас, що ні від кого не успадковується, — базовий. У Swift немає спільного кореневого класу на кшталт System.Object: якщо суперклас не вказано, клас просто стає базовим.

Приклад — базовий екран застосунку, який знає свою назву для аналітики й реагує на показ:

Swift
class Screen {
    var title = ""
    var analyticsName: String {
        "screen_" + title.lowercased()
    }
    func didAppear() {
        print("track:", analyticsName)
    }
}

Підкласи

Суперклас пишуть після двокрапки. Підклас отримує все від суперкласу і може додати своє:

Swift
class PaywallScreen: Screen {
    var variant = "control"
}

let paywall = PaywallScreen()
paywall.title = "Paywall"
paywall.variant = "b"
paywall.didAppear()   // track: screen_paywall

Підклас теж можна успадковувати — ланцюжок будь-якої глибини.

C#

Те саме, що class PaywallScreen : Screen. Множинного успадкування класів немає, як і в C#. Протоколи (аналог інтерфейсів) пишуться в тому ж списку після двокрапки, суперклас — першим.

Перевизначення

Щоб перевизначити метод, властивість чи сабскрипт, обов'язково пишуть override. Без нього перевизначення — помилка компіляції, а override без відповідного члена в суперкласі — теж помилка. Так випадкове перевизначення неможливе.

Звернення до super

Реалізацію суперкласу викликають через super: super.didAppear(), super.analyticsName, super[index].

Перевизначення методів

Swift
class OnboardingScreen: Screen {
    var step = 1
    override func didAppear() {
        super.didAppear()                      // базова аналітика
        print("onboarding step \(step) shown")
    }
}

let screens: [Screen] = [PaywallScreen(), OnboardingScreen()]
for s in screens { s.didAppear() }   // викликається реалізація підкласу
C#

У Swift усі методи класу за замовчуванням «віртуальні» — немає потреби в virtual. Натомість override обов'язковий завжди. Поведінки new (приховування методу) немає.

Перевизначення властивостей

Перевизначити можна будь-яку успадковану властивість, і для підкласу неважливо, як вона влаштована в суперкласі: збережена чи обчислювана — у override var однаково пишуть ім'я, тип і власні get/set.

Swift
class ExperimentPaywall: PaywallScreen {
    override var analyticsName: String {
        super.analyticsName + "_" + variant    // screen_paywall_b
    }
}

Правила:

  • Властивість лише для читання можна зробити read-write, додавши сеттер.
  • Read-write властивість не можна зробити read-only.
  • Якщо додаєш сеттер, мусиш дати й геттер (хоча б super.property).

Перевизначення спостерігачів

Підклас може додати willSet/didSet до успадкованої властивості, навіть якщо суперклас про це нічого не знає:

Swift
class LoggedScreen: Screen {
    override var title: String {
        didSet { print("Заголовок змінено: \(oldValue) → \(title)") }
    }
}

Не можна додавати спостерігачі до успадкованих констант і read-only властивостей — їх неможливо змінити. Якщо ти вже перевизначаєш сеттер, didSet поруч не потрібен (і не дозволений) — реакцію на зміну пиши в самому сеттері.

Перевизначення членів типу

Перевизначати можна не лише члени екземпляра, а й методи та обчислювані властивості типу, оголошені через class (на відміну від static, які перевизначати не можна):

Swift
class Screen2 {
    class var defaultTransition: String { "push" }
    class func make() -> Screen2 { Screen2() }
}

class ModalScreen: Screen2 {
    override class var defaultTransition: String { "modal" }
    override class func make() -> Screen2 { ModalScreen() }
}

Заборона перевизначення

final перед методом, властивістю чи сабскриптом забороняє перевизначати їх у підкласах (зокрема й члени, додані в розширенні). final class забороняє успадковувати клас взагалі.

Swift
final class SettingsScreen: Screen { }
// class DebugSettings: SettingsScreen { }    // помилка

class HomeScreen: Screen {
    final override func didAppear() { }       // далі перевизначати не можна
}
Порада

Позначай класи final за замовчуванням. Це стандартна практика в Swift: компілятор робить прямі виклики замість динамічних, а відкритість для успадкування — свідоме рішення. У Swift-коді глибокі ієрархії рідкість — поведінку частіше збирають з протоколів і композиції.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що станеться, якщо в підкласі оголосити метод з тим самим ім'ям, що в суперкласі, але без override?

У Swift override обов'язковий. Випадкове перевизначення неможливе, а поведінки new немає.

2. Чи треба позначати метод класу як virtual, щоб його можна було перевизначити?

Методи класів у Swift «віртуальні» за замовчуванням. Заборонити перевизначення можна словом final. Для підкласів з іншого модуля метод ще має бути open.

3. Що робить final class PaywallScreen: Screen?

final перед класом забороняє наслідування. Бонус — компілятор може робити прямі виклики замість динамічних.

4. Яке твердження неправильне?

Підклас може розширити можливості властивості, але не звузити їх: код, що працює з суперкласом, очікує, що запис можливий.

5. Скільки суперкласів може мати клас у Swift?

Як і в C#, суперклас лише один. Множинність досягають протоколами.

Практика
  1. Зроби ієрархію Purchase → SubscriptionPurchase, ConsumablePurchase з перевизначеною обчислюваною властивістю displayPrice і методом describe(), що викликає super.describe().
  2. Додай до підкласу спостерігач didSet на успадковану властивість і переконайся, що спостерігач суперкласу теж викликається.
  3. Спробуй перевизначити let-властивість і read-write властивість як read-only. Прочитай повідомлення компілятора.
  4. Перепиши ієрархію з пункту 1 на протокол Purchase і структури. Що стало простіше, а що складніше?
