Властивості

Збережені й обчислювані властивості, lazy, спостерігачі willSet/didSet, property wrappers з projected value, глобальні змінні та властивості типу.

У книзі: properties

Збережені властивості

Збережена властивість — let чи var усередині структури або класу; enum збережених властивостей екземпляра не має. Що можна змінювати, визначають дві речі одночасно: як оголошено властивість і як оголошено сам екземпляр.

Swift
struct Order {
    let id: UUID            // не змінюється ніколи
    var status = "new"      // змінюється, якщо змінюваний сам екземпляр
}

final class OrderBox {
    let id = UUID()
    var status = "new"
}
var order = Order(...) let order = Order(...) let box = OrderBox()
.status = "paid" ✓ ✗ — let заморожує все значення структури ✓ — let фіксує лише посилання
.id = UUID() ✗ ✗ ✗

Звідси корисна звичка: моделі даних робити структурами з var-полями, а «незмінність» вирішувати на рівні змінної (let), а не прописувати в кожному полі.

Ліниві властивості

lazy var обчислює початкове значення при першому зверненні. Корисно, коли значення дороге або залежить від стану, що з'явиться після ініціалізації:

Swift
import Foundation

final class PriceFormatter {
    var currencyCode = "UAH"

    // NumberFormatter дорогий у створенні; до того ж налаштування
    // залежить від currencyCode, тому обчислюємо в момент першого використання
    lazy var formatter: NumberFormatter = {
        let f = NumberFormatter()
        f.numberStyle = .currency
        f.currencyCode = currencyCode       // у lazy можна звертатися до self
        return f
    }()

    func format(_ value: Double) -> String {
        formatter.string(from: value as NSNumber) ?? "\(value)"
    }
}

Чому lazy буває лише з var: значення з'являється вже після того, як об'єкт створено, а let мусить отримати значення до кінця init. Зате саме тому у виразі lazy-властивості доступний self.

Пастка

lazy не потокобезпечна. Якщо два потоки одночасно вперше звернуться до властивості, ініціалізатор може виконатися двічі. У Swift 6 компілятор і так не дасть ділити змінюваний стан між потоками без синхронізації, але пам'ятай про це.

C#

Аналог — Lazy<T>, тільки вбудований у мову і без .Value.

Де «бекінг-поле»?

У C# поряд з властивістю часто живе приватне поле _status. У Swift збережена властивість сама і є сховищем — окремого поля немає й не потрібно. Якщо потрібна логіка навколо запису, її додають спостерігачами або обгорткою (нижче), а не ручним полем.

Обчислювані властивості

Обчислювана властивість нічого не зберігає: вона має геттер і, за бажанням, сеттер.

Swift
struct Countdown {
    var totalSeconds = 0

    var minutesAndSeconds: (minutes: Int, seconds: Int) {
        get {
            (totalSeconds / 60, totalSeconds % 60)
        }
        set(parts) {
            totalSeconds = parts.minutes * 60 + parts.seconds
        }
    }
}

var timer = Countdown(totalSeconds: 135)
print(timer.minutesAndSeconds)        // (minutes: 2, seconds: 15)
timer.minutesAndSeconds = (5, 0)
print(timer.totalSeconds)             // 300

Скорочений сеттер

Якщо не вказати ім'я параметра сеттера, воно буде newValue:

Swift
set {
    totalSeconds = newValue.minutes * 60 + newValue.seconds
}

Скорочений геттер

Тіло геттера з одного виразу повертає його без return (як і в функціях).

Властивості лише для читання

Без сеттера властивість доступна лише для читання. Тоді get { } можна не писати:

Swift
struct Cart {
    var prices: [Double]
    var total: Double { prices.reduce(0, +) }
}

Ключове слово тут завжди var — навіть для властивості лише для читання: її значення обчислюється щоразу заново, тож константою вона не є.

C#

Те саме, що властивості з get/set у C#. Відмінність лише в тому, що збережена властивість (як auto-property) і обчислювана виглядають по-різному: перша — var x = 0, друга — var x: Int { ... }.

Спостерігачі властивостей

willSet і didSet реагують на кожне присвоєння значення, навіть якщо нове значення дорівнює старому.

Swift
final class Player {
    var health = 100 {
        willSet {
            print("Здоров'я зміниться на \(newValue)")
        }
        didSet {
            if health <= 0 { print("Гравець переможений") }
            if health > 100 { health = 100 }   // присвоєння в didSet не викликає спостерігачів повторно
        }
    }
}
  • У willSet нове значення — newValue, у didSet старе — oldValue. Імена можна змінити: willSet(next), didSet(previous).
  • Спостерігачі можна додати до власних збережених властивостей, до успадкованих (збережених і обчислюваних) через override, але не до власних обчислюваних — там і так є сеттер.
  • Під час ініціалізації в init спостерігачі не викликаються для власних властивостей. Спостерігачі суперкласу викликаються, коли підклас присвоює властивість після виклику super.init.
Пастка

increment(&score) спрацює didSet у score навіть тоді, коли функція нічого не змінила: inout наприкінці завжди записує значення назад. Якщо didSet шле подію в аналітику, порівнюй oldValue з новим значенням.

Property wrappers

Property wrapper відокремлює логіку зберігання від оголошення властивості. Класичний iOS-приклад — налаштування, що мають жити в UserDefaults:

Swift
import Foundation

@propertyWrapper
struct Stored<Value> {
    let key: String
    let defaultValue: Value
    var storage: UserDefaults = .standard

    var wrappedValue: Value {
        get { storage.object(forKey: key) as? Value ?? defaultValue }
        set { storage.set(newValue, forKey: key) }
    }
}

struct AppSettings {
    @Stored(key: "hasSeenOnboarding", defaultValue: false) var hasSeenOnboarding: Bool
    @Stored(key: "launchCount", defaultValue: 0) var launchCount: Int
}

var settings = AppSettings()
settings.launchCount += 1          // читає й пише UserDefaults під капотом

Обгортка — структура, клас чи enum з атрибутом @propertyWrapper і властивістю wrappedValue. Для @Stored var launchCount компілятор створює приватне поле _launchCount типу Stored<Int> і властивість launchCount, що звертається до _launchCount.wrappedValue.

Як обгортка отримує початкові значення

Що саме викличеться, залежить від того, як записано оголошення:

Запис Ініціалізатор обгортки
@W var x: T init()
@W var x = value init(wrappedValue: value)
@W(a: 1) var x: T init(a: 1) — як у @Stored(key:defaultValue:) вище
@W(a: 1) var x = value init(wrappedValue: value, a: 1)

Тобто значення після = завжди йде в параметр wrappedValue, а аргументи атрибута — в інші параметри. Якщо обгортка підтримує кілька форм, у неї просто кілька ініціалізаторів.

Projected value

Обгортка може надавати додаткове значення через властивість projectedValue. Доступ до нього — через $ перед іменем:

Swift
@propertyWrapper
struct Tracked<Value> {
    private(set) var changeCount = 0
    var wrappedValue: Value {
        didSet { changeCount += 1 }
    }
    init(wrappedValue: Value) { self.wrappedValue = wrappedValue }
    var projectedValue: Int { changeCount }
}

struct Profile {
    @Tracked var nickname = "guest"
}

var p = Profile()
p.nickname = "neo"
p.nickname = "trinity"
print(p.$nickname)   // 2

Усередині типу до projected value звертаються без self.: просто $nickname. Projected value може бути будь-якого типу — навіть самою обгорткою (var projectedValue: Self { self }).

Саме так працюють @State і @Binding у SwiftUI (а також @Bindable): $name — це projected value, яке дає Binding. У @Environment projected value немає.

Глобальні й локальні змінні

Збережені й обчислювані змінні, а також спостерігачі можна оголошувати і поза типами — глобально або локально у функції.

  • Глобальні константи й змінні в бібліотечних файлах ініціалізуються ліниво при першому зверненні, без lazy, і потокобезпечно — рівно один раз. Виняток — код верхнього рівня в main.swift чи скрипті: там змінні ініціалізуються по черзі, як звичайні інструкції.
  • Локальні — ніколи не ліниві, якщо не позначені lazy.
  • Property wrappers можна застосовувати до локальних змінних, але не до глобальних.
Swift 6

Глобальна var — це змінюваний стан, доступний з будь-якого потоку. У режимі Swift 6 компілятор відмовиться її компілювати, поки ти не ізолюєш її глобальним актором (@MainActor var) або не зробиш let з Sendable-типом.

Властивості типу

Властивості, що належать самому типу, а не екземпляру, — аналог static у C#.

Swift
@MainActor          // змінювана статична властивість — це глобальний стан, тож ізолюємо її
struct FeatureFlags {
    static let configVersion = 3
    static var isNewPaywallEnabled = false
    static var summary: String { "v\(configVersion), paywall: \(isNewPaywallEnabled)" }
}

class Theme {
    class var accentColor: String { "orange" }   // підклас може перевизначити
}

FeatureFlags.isNewPaywallEnabled = true
print(FeatureFlags.summary)
  • static let/static var пишуть одразу зі значенням: ініціалізатора, який би їх заповнив, у типу немає.
  • Значення обчислюється при першому зверненні й рівно один раз, навіть якщо звертаються кілька потоків одночасно — тому static let shared = ... є стандартним способом зробити синглтон.
  • class var у класах дозволяє перевизначати обчислювану властивість типу в підкласах. static — забороняє.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що станеться з цим кодом?

Swift
struct Order { var status = "new" }
let order = Order()
order.status = "paid"

Для структури let робить незмінним усе значення, навіть var-властивості. З класом присвоєння спрацювало б.

2. Коли обчислюється lazy var formatter = NumberFormatter()?

lazy відкладає створення значення до першого звернення. Аналог Lazy<T> у C#, але без .Value.

3. Яке твердження про обчислювані властивості неправильне?

Обчислювані властивості завжди оголошують через var, навіть лише для читання: їхнє значення може бути щоразу іншим.

4. Які імена мають значення в спостерігачах willSet і didSet за замовчуванням?

Перед зміною доступне майбутнє значення (newValue), після — попереднє (oldValue).

5. Що повертає $name для властивості з property wrapper?

$ дає доступ до projectedValue обгортки. Сама обгортка зберігається в прихованому полі _name.

Практика
  1. Зроби структуру Price зі збереженою ціною в копійках (Int) і обчислюваною hryvnias: Double з геттером і сеттером.
  2. Додай до класу Wallet властивість coins з didSet, який відправляє подію аналітики, тільки якщо значення справді змінилося.
  3. Напиши property wrapper @History для будь-якого типу, projected value якого — масив усіх попередніх значень.
  4. Напиши обгортку @UserDefault(key:defaultValue:), що читає й пише значення в UserDefaults.
