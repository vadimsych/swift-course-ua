Довідник (за потреби) · урок 35

Довідник: атрибути

Атрибути додають інформацію до оголошень і типів: доступність API, макроси, @main, dynamic member lookup, property wrappers і result builders, атрибути для Objective-C, бібліотек і конкурентності, а також атрибути типів (@escaping, @Sendable, @autoclosure) і @unknown.

У книзі: attributes

Атрибут пишеться через @ перед оголошенням або типом, деякі приймають аргументи в дужках: @available(iOS 18, *).

Атрибути оголошень

attached і freestanding

@attached(роль, names: ...) і @freestanding(роль) застосовуються до оголошень макросів і описують, як макрос можна використовувати (урок 19).

Ролі attached-макросів: peer, accessor, memberAttribute, member, extension, body. Ролі freestanding: expression, declaration.

Аргумент names: перелічує імена, які створить макрос: named(x), overloaded, prefixed(_), suffixed(Mock), arbitrary. Для extension-ролі додатково вказують conformances: — протоколи, які додасть макрос.

Body-макроси (@attached(body)) генерують тіло функції, оголошеної без тіла або з існуючим тілом, яке макрос замінює чи обгортає — наприклад, для автоматичного логування чи трасування виклику.

available

Описує доступність оголошення на платформах і версіях:

Swift
@available(iOS 17, macOS 14, *)
func newFeature() { }

@available(*, deprecated, message: "Використовуй loadAsync()")
func load() { }

@available(iOS, introduced: 15, deprecated: 17, obsoleted: 18, renamed: "fetch()")
func oldFetch() { }

@available(*, unavailable)
extension Session: Sendable { }

@available(*, noasync, message: "Блокує потік")
func waitSync() { }

@available(swift 6)
func onlySwift6Mode() { }

Аргументи:

  • платформа (iOS, macOS, watchOS, tvOS, visionOS, macCatalyst, *, а також розширення: iOSApplicationExtension тощо);
  • introduced, deprecated, obsoleted — версії; deprecated без версії — застаріле без конкретної версії;
  • unavailable — недоступне взагалі;
  • message, renamed — пояснення й нове ім'я (Xcode запропонує fix-it);
  • noasync — не можна викликати з асинхронного контексту;
  • swift замість платформи — доступність за версією мови; таку форму не поєднують з платформами й *.

Скорочена форма @available(iOS 17, macOS 14, *) еквівалентна кільком introduced.

backDeployed

Дозволяє бібліотеці «підставити» реалізацію нового API для старих ОС, де його ще немає в системі:

Swift
@available(iOS 16, *)
@backDeployed(before: iOS 18)
public func formattedPrice() -> String { ... }

На старих системах викличеться копія функції з застосунку, на нових — системна. Потрібно лише авторам бібліотек.

discardableResult

Прибирає попередження про невикористаний результат функції.

dynamicCallable

Дозволяє викликати екземпляр як функцію з довільною кількістю аргументів. Тип мусить реалізувати dynamicallyCall(withArguments:) та/або dynamicallyCall(withKeywordArguments:):

Swift
@dynamicCallable
struct Logger {
    func dynamicallyCall(withKeywordArguments args: KeyValuePairs<String, Any>) {
        print(args.map { "\($0.key)=\($0.value)" }.joined(separator: " "))
    }
}

let log = Logger()
log(event: "purchase", price: 4.99)   // event=purchase price=4.99

Застосовується для взаємодії з динамічними мовами (Python, JavaScript).

dynamicMemberLookup

Звертання value.будь_яке_ім'я компілятор перетворює на виклик subscript(dynamicMember:). Є два варіанти сабскрипта:

  • з параметром-рядком (String) — ім'я передається як текст; так роблять обгортки над словниками чи динамічними мовами, і помилку в імені компілятор не впіймає;
  • з параметром-key path — звертання перевіряється компілятором; якщо є обидва сабскрипти, перевагу має key path.

Приклад з key path — тема оформлення, що «пропускає» звертання до вкладеної палітри:

Swift
struct Palette { var accent = "orange"; var background = "white" }

@dynamicMemberLookup
struct Theme {
    var name: String
    var palette = Palette()

    subscript<T>(dynamicMember path: WritableKeyPath<Palette, T>) -> T {
        get { palette[keyPath: path] }
        set { palette[keyPath: path] = newValue }
    }
}

var dark = Theme(name: "Dark")
dark.accent = "teal"        // насправді dark.palette.accent
print(dark.background)      // "white"
// dark.font                // помилка компіляції: у Palette немає font

export

Застосовується до функцій і методів бібліотек і керує тим, що саме з них бачать клієнтські модулі:

  • @export(interface) — клієнти отримують лише символ для виклику; тіло функції для них закрите, його не можна вбудувати чи оптимізувати разом з їхнім кодом. Так ховають реалізацію.
  • @export(implementation) — навпаки, у бінарник бібліотеки символ не потрапляє, а клієнти отримують тіло й самі вбудовують його копію там, де потрібно. Так можна додати нову функцію, не змінюючи ABI бібліотеки.

frozen

Для авторів бібліотек: обіцянка, що тип не змінить свого складу в наступних версіях. Для enum це означає, що @unknown default у switch не потрібен.

GKInspectable

Робить властивість доступною для редагування в редакторі сцен SpriteKit/GameplayKit у Xcode.

globalActor

Позначає тип як глобальний актор, щоб його ім'я можна було використовувати як атрибут ізоляції (урок 18). Це може бути актор, структура, enum чи final клас — головне, щоб статична властивість shared повертала екземпляр актора.

inlinable

Тіло публічної функції стає частиною інтерфейсу модуля, і клієнти можуть його вбудовувати й спеціалізувати. Код усередині може використовувати лише public або @usableFromInline сутності.

main

Позначає тип, що є точкою входу програми. Тип має статичний main(), можливо async throws:

Swift
@main
struct Tool {
    static func main() async throws {
        print("Старт")
    }
}

У SwiftUI @main struct MyApp: App працює так само: протокол App надає реалізацію main().

nonobjc

Забороняє показувати метод, властивість чи ініціалізатор в Objective-C, навіть якщо тип — @objc.

NSApplicationMain і UIApplicationMain

Старі атрибути точки входу для AppKit і UIKit. У режимі Swift 6 вони вже помилка компіляції — замість них використовують @main на класі делегата застосунку.

NSCopying

На властивості класу: при присвоєнні зберігається копія значення через copy(with:), а не саме значення. Тип має відповідати NSCopying.

NSManaged

Для властивостей підкласів NSManagedObject (Core Data): сховище і реалізацію надає Core Data в рантаймі.

objc

Робить оголошення доступним з Objective-C. Потрібен для #selector, KVO і старих UIKit-делегатів. Можна задати інше ім'я: @objc(showPaywall:).

objcMembers

На класі — автоматично додає @objc до всіх його членів (і членів розширень). Збільшує розмір бінарника, тож використовується обмежено.

preconcurrency

Пом'якшує перевірки конкурентності для коду, написаного до Swift Concurrency:

  • @preconcurrency import Module — попередження про Sendable з цього модуля приглушуються;
  • @preconcurrency на оголошенні — клієнти, що ще не перейшли на сувору перевірку, не отримають помилок від нових анотацій;
  • @preconcurrency на відповідності протоколу — дозволяє ізольованому типу відповідати неізольованому протоколу з перевіркою в рантаймі.

propertyWrapper

Позначає тип як обгортку властивості (урок 10).

resultBuilder

Позначає тип як result builder (урок 29). Перетворення, які застосовує компілятор:

  • кожен вираз → buildExpression(_:) (якщо є);
  • послідовність → buildBlock(_:...) або попарно через buildPartialBlock(first:) і buildPartialBlock(accumulated:next:);
  • if без else → buildOptional(_:);
  • if-else, switch → вкладені buildEither(first:)/buildEither(second:);
  • for → buildArray(_:);
  • if #available → buildLimitedAvailability(_:);
  • результат → buildFinalResult(_:) (якщо є).

Усередині builder-замикання не працюють return, break, guard, while і do-catch.

Атрибут builder-а застосовують до параметра-замикання функції, до самої функції чи методу та до геттера обчислюваної властивості — тоді їхнє тіло перетворюється за правилами builder-а.

requires_stored_property_inits

На класі: кожна збережена властивість мусить мати значення за замовчуванням в оголошенні.

testable

На import у тестах: дає доступ до internal-сутностей модуля, зібраного з увімкненим тестуванням, а internal і public класи та їхні члени для тестового коду поводяться як open — їх можна успадковувати й перевизначати в моках.

unchecked

На відповідності протоколу (@unchecked Sendable) — вимикає перевірку компілятором вимог протоколу. Підтримується лише для Sendable. Відповідальність за коректність на тобі.

usableFromInline

Робить internal-сутність доступною для використання в @inlinable-коді, не відкриваючи її як public.

warn_unqualified_access

На методі: компілятор попередить, якщо метод викликано без явного self. чи імені типу. Допомагає уникнути плутанини з глобальними функціями з тим самим ім'ям (як min/max).

Атрибути Interface Builder

@IBOutlet, @IBAction, @IBSegueAction, @IBInspectable, @IBDesignable — зв'язок коду з елементами в сторібордах і XIB. Усі вони неявно додають @objc (так само, як @NSManaged і @GKInspectable).

Атрибути типів

autoclosure

На параметрі функціонального типу без параметрів: аргумент-вираз автоматично загортається в замикання й обчислюється ліниво (урок 7).

convention

Задає конвенцію виклику функціонального типу:

  • @convention(swift) — звичайне Swift-замикання (за замовчуванням);
  • @convention(block) — Objective-C блок;
  • @convention(c) — вказівник на C-функцію, не може захоплювати контекст.

escaping

Параметр-замикання може пережити виклик функції (урок 7).

Sendable

@Sendable на функціональному типі: замикання безпечно передавати між областями ізоляції — воно захоплює лише Sendable-значення й не змінює захоплені змінні.

Атрибути гілок switch

unknown

@unknown default (або @unknown case _) — гілка для варіантів enum, що можуть з'явитися в майбутніх версіях бібліотеки. Компілятор попереджає, якщо відомі варіанти не оброблено явно (урок 33).

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. До чого застосовують атрибути @attached(...) і @freestanding(...)?

Ці атрибути задають вид макросу та його ролі, наприклад member чи expression.

2. Чому тут помилка компіляції?

Swift
@available(*, unavailable, message: "Використовуй newLoad()")
func load() {}

load()

@available(*, unavailable) робить оголошення недоступним на всіх платформах, тож виклик — помилка.

3. Для чого бібліотеці атрибут @backDeployed(before: iOS 18)?

Так бібліотека «підставляє» реалізацію нового API для систем, де його ще немає.

4. Що надрукує цей код?

Swift
@discardableResult
func save() -> Bool {
    print("saved")
    return true
}
save()

Друкує лише сама функція; @discardableResult просто прибирає попередження про невикористаний результат.

5. Що надрукує цей код?

Swift
@dynamicCallable
struct Summer {
    func dynamicallyCall(withArguments args: [Int]) -> Int {
        args.reduce(0, +)
    }
}
let sum = Summer()
print(sum(1, 2, 3))

З @dynamicCallable виклик sum(1, 2, 3) перетворюється на dynamicallyCall(withArguments: [1, 2, 3]).

6. Чому тут помилка компіляції?

Swift
struct Palette { var accent = "orange" }

@dynamicMemberLookup
struct Theme {
    var palette = Palette()
    subscript<T>(dynamicMember path: KeyPath<Palette, T>) -> T {
        palette[keyPath: path]
    }
}

let theme = Theme()
print(theme.font)

Варіант з key path перевіряється компілятором, тож неіснуюче ім'я — помилка компіляції.

7. Що означає @frozen на публічному enum бібліотеки?

@frozen — обіцянка авторів бібліотеки, що нових варіантів не з'явиться.

8. Яка головна вимога до типу з атрибутом @globalActor?

Глобальним актором може бути актор, структура, enum чи final клас — головне, щоб shared повертала актор.

9. Що може використовувати тіло @inlinable-функції?

Тіло стає частиною інтерфейсу модуля, тому все, що воно використовує, має бути доступне клієнтам.

10. Яке твердження про @main неправильне?

Точка входу в програмі лише одна.

11. Що відбувається з @UIApplicationMain у режимі Swift 6?

Старі атрибути точки входу в режимі Swift 6 заборонені — їх замінює @main.

12. Що робить @preconcurrency import LegacySDK?

Це спосіб працювати зі старим модулем, написаним до Swift Concurrency, без потоку попереджень.

13. Що надрукує цей код?

Swift
@resultBuilder
struct ListBuilder {
    static func buildBlock(_ parts: String...) -> [String] { parts }
}

@ListBuilder
func menu() -> [String] {
    "Home"
    "Paywall"
}
print(menu())

Атрибут builder-а на функції перетворює її тіло: обидва вирази передаються в buildBlock.

14. Що дає @testable import PaywallKit у тестах?

Модуль має бути зібраний з увімкненим тестуванням; private і fileprivate так і лишаються закритими.

15. Для якого протоколу підтримується @unchecked у відповідності?

@unchecked Sendable вимикає перевірку компілятором, і відповідальність за коректність на тобі.

16. Що надрукує цей код?

Swift
func log(_ message: @autoclosure () -> String, enabled: Bool) {
    if enabled { print(message()) }
}
func make() -> String {
    print("build")
    return "msg"
}
log(make(), enabled: false)
print("done")

@autoclosure загортає аргумент у замикання, а воно не викликається при enabled: false, тож make() не виконується.

17. Яка особливість функціонального типу з @convention(c)?

@convention(block) — Objective-C блок, @convention(swift) — звичайне замикання.

18. Чому тут помилка компіляції?

Swift
final class Store {
    var handlers: [() -> Void] = []
    func add(_ handler: () -> Void) {
        handlers.append(handler)
    }
}

За замовчуванням параметр-замикання non-escaping і не може пережити виклик функції.

19. Що гарантує @Sendable на функціональному типі?

Такі замикання безпечно передавати між областями ізоляції.

20. Навіщо в switch по enum із бібліотеки пишуть @unknown default?

На відміну від звичайного default, компілятор усе одно попередить, якщо відомі варіанти не оброблено явно.

Практика
  1. Познач функцію як @available(*, deprecated, renamed: "newName()") і подивись, який fix-it пропонує Xcode.
  2. Зроби обгортку @dynamicMemberLookup над конфігом, що проксує доступ до властивостей вкладеної структури через key path.
  3. Створи консольну програму з @main struct і static func main() async.
  4. Знайди в документації SwiftUI три атрибути з цього уроку й поясни, навіщо вони там.
