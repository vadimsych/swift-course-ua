Розширення

extension додає функціональність до будь-якого існуючого типу, навіть чужого: обчислювані властивості, методи, ініціалізатори, сабскрипти, вкладені типи й відповідність протоколам.

У книзі: extensions

Синтаксис

Swift
extension SomeType {
    // нова функціональність
}

extension SomeType: SomeProtocol, AnotherProtocol {
    // реалізація протоколів
}

Розширювати можна класи, структури, перелічення й протоколи, зокрема типи зі стандартної бібліотеки, Foundation і сторонніх SDK. Розширення generic-типу може додавати обмеження (урок про узагальнення).

Що розширення не можуть:

  • додавати збережені властивості й спостерігачі до існуючих властивостей;
  • перевизначати існуючу функціональність;
  • додавати designated-ініціалізатори чи deinit до класів.

Розширення — частина типу на етапі компіляції, тож його члени доступні в усіх екземплярах, де б їх не створили.

C#

Як extension methods, але без статичного класу. Extension members у C# 14 уже вміють властивості, а от ініціалізатори й реалізацію інтерфейсу додати не можуть — у Swift розширення може і те, і інше.

Обчислювані властивості

Swift
extension Double {
    /// 0.256 → "25.6%"
    var asPercent: String {
        (self * 100).formatted(.number.precision(.fractionLength(0...1))) + "%"
    }
}

let conversion = 0.256
print(conversion.asPercent)   // "25.6%" — роздільник залежить від локалі пристрою

Ініціалізатори

Розширення можуть додавати convenience-ініціалізатори до класів і будь-які ініціалізатори до value types.

Важлива техніка: якщо додати ініціалізатор структурі в розширенні, автоматичні ініціалізатори (за замовчуванням і memberwise) зберігаються:

Swift
struct RGB {
    var r = 0.0, g = 0.0, b = 0.0
}

extension RGB {
    init(hex: UInt32) {
        self.init(r: Double((hex >> 16) & 0xFF) / 255,
                  g: Double((hex >> 8) & 0xFF) / 255,
                  b: Double(hex & 0xFF) / 255)
    }
}

let a = RGB()                  // за замовчуванням — збережено
let b = RGB(r: 1, g: 0, b: 0)  // memberwise — збережено
let c = RGB(hex: 0xFF8800)     // з розширення

Автоматичні ініціалізатори зберігаються, лише якщо всі збережені властивості мають значення за замовчуванням (для ініціалізатора без параметрів) і в самому оголошенні структури немає власних ініціалізаторів.

Особливе правило для структур з іншого модуля: ініціалізатор у розширенні не може звертатися до self, доки не викличе якийсь ініціалізатор, оголошений у модулі-власнику типу. Так модуль-власник зберігає контроль над тим, як створюються його значення.

Методи

Swift
extension Array {
    /// [1, 2, 3, 4, 5].chunked(into: 2) → [[1, 2], [3, 4], [5]]
    func chunked(into size: Int) -> [[Element]] {
        stride(from: 0, to: count, by: size).map {
            Array(self[$0..<Swift.min($0 + size, count)])
        }
    }
}

let batches = Array(1...7).chunked(into: 3)   // [[1, 2, 3], [4, 5, 6], [7]]

Мутуючі методи

Методи, що змінюють value type, позначаються mutating, як і в самому типі:

Swift
extension Int {
    mutating func clamp(to range: ClosedRange<Int>) {
        self = Swift.min(Swift.max(self, range.lowerBound), range.upperBound)
    }
}

var volume = 140
volume.clamp(to: 0...100)   // 100

Сабскрипти

Swift
extension UInt8 {
    /// Прапорець на позиції 0…7, наприклад набір вимкнених звуків.
    subscript(flag index: Int) -> Bool {
        get { (self >> index) & 1 == 1 }
        set {
            if newValue { self |= (1 << index) } else { self &= ~(1 << index) }
        }
    }
}

var mutedChannels: UInt8 = 0
mutedChannels[flag: 2] = true
mutedChannels[flag: 2]   // true
mutedChannels            // 4

Вкладені типи

Розширення може додати в тип вкладений тип — зручно, щоб згрупувати константи чи допоміжні моделі поруч з кодом, який їх використовує:

Swift
import Foundation

extension URLRequest {
    struct RetryHint {
        let attempts: Int
        let backoff: TimeInterval
    }

    static let defaultRetry = RetryHint(attempts: 3, backoff: 0.5)   // статична властивість

    static func authorized(_ url: URL, token: String) -> URLRequest {  // статичний метод
        var request = URLRequest(url: url)
        request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
        return request
    }
}

let hint = URLRequest.defaultRetry
let request = URLRequest.authorized(URL(string: "https://api.example.com/me")!, token: "abc")

Як видно, розширення можуть додавати й статичні властивості та методи — так само, як члени екземпляра. Статичні збережені властивості (static let) теж дозволені, на відміну від збережених властивостей екземпляра.

Як використовують розширення на практиці

  • Організація коду. Відповідність кожному протоколу — в окремому розширенні: extension PaywallView: UITableViewDataSource { }. Так файл читається блоками.
  • Відокремлення приватних помічників: private extension ProfileViewModel { ... }.
  • Збереження memberwise-ініціалізатора — власні init у розширенні.
  • Ретроактивне моделювання: додати чужому типу відповідність своєму протоколу.
Пастка

Якщо твій модуль і стороння бібліотека додадуть до одного типу методи з однаковою сигнатурою, виникне конфлікт. Для розширень системних типів у бібліотеках давай імена з префіксом або роби їх internal/private.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Чому тут помилка компіляції?

Swift
struct Point {
    var x = 0
}

extension Point {
    var y = 0
}

Розширення не змінює розмір і розкладку типу в пам'яті, тож додає лише обчислювані властивості.

2. Що з цього розширення не може?

Розширення додає нове, але не замінює те, що вже є в типі.

3. Що надрукує цей код?

Swift
extension Int {
    var squared: Int { self * self }
    var isEven: Bool { self % 2 == 0 }
}
print(7.squared, 7.isEven)

Розширення додало Int дві обчислювані властивості, і їх можна викликати навіть на літералі.

4. Що надрукує цей код?

Swift
struct Size {
    var w = 0, h = 0
}

extension Size {
    init(side: Int) {
        self.init(w: side, h: side)
    }
}

let a = Size()
let b = Size(w: 2, h: 3)
let c = Size(side: 4)
print(a.w + b.h + c.w)

Ініціалізатор у розширенні не прибирає автоматичні: 0 + 3 + 4.

5. Чому тут помилка компіляції?

Swift
struct Size {
    var w = 0, h = 0
    init(side: Int) {
        w = side
        h = side
    }
}

let b = Size(w: 2, h: 3)

Щоб зберегти memberwise-ініціалізатор, власний init переносять у розширення.

6. Які ініціалізатори розширення може додати до класу?

Designated-ініціалізатори й deinit класу пишуть лише в основному оголошенні.

7. Що надрукує цей код?

Swift
extension String {
    func repeated(_ n: Int) -> String {
        String(repeating: self, count: n)
    }
}
print("ab".repeated(3))

Розширення додало метод до String, і він доступний усім рядкам.

8. Чому тут помилка компіляції?

Swift
extension Int {
    func double() {
        self *= 2
    }
}

Як і в самому типі, метод розширення, що змінює структуру, позначають mutating.

9. Що надрукує цей код?

Swift
extension Int {
    mutating func clamp(to range: ClosedRange<Int>) {
        self = Swift.min(Swift.max(self, range.lowerBound), range.upperBound)
    }
}

var level = -5
level.clamp(to: 0...10)
print(level)

mutating-метод замінює self на значення в межах діапазону.

10. Що надрукує цей код?

Swift
extension String {
    subscript(char i: Int) -> Character {
        self[index(startIndex, offsetBy: i)]
    }
}
print("Swift"[char: 1])

Сабскрипт з міткою char: повертає символ з індексом 1, рахуючи від нуля.

11. Що надрукує цей код?

Swift
extension Int {
    enum Sign { case negative, zero, positive }

    var sign: Sign {
        if self < 0 { return .negative }
        return self == 0 ? .zero : .positive
    }
}
print((-3).sign, 0.sign)

Розширення додало в Int вкладений enum і властивість, що його повертає.

12. Що з цього можна додати в розширенні?

Статичні збережені властивості дозволені, а збережені властивості екземпляра — ні.

13. Як називається прийом, коли чужому типу додають відповідність власному протоколу через розширення?

Так можна, наприклад, зробити системний тип сумісним зі своєю абстракцією, не змінюючи його код.

14. Чому методи в розширеннях системних типів у бібліотеці варто робити internal/private або давати їм префікс?

Два модулі, що додають той самий метод до одного типу, конфліктують.

Практика
  1. Розшир Date обчислюваними властивостями isToday, startOfDay і методом adding(days:).
  2. Розшир String ініціалізатором init(price: Decimal, currency: String), що форматує ціну.
  3. Розшир Array where Element == Int методом average() -> Double?.
  4. Розбий будь-який свій великий клас на основне оголошення та кілька розширень за відповідальністю.
