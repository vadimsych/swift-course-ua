Перелічення

Enum у Swift — це не набір іменованих чисел, як у C#, а повноцінний тип: з асоційованими значеннями, методами, протоколами й рекурсією. Мабуть, найпотужніший інструмент моделювання в мові.

У книзі: enumerations

Синтаксис

Swift
enum SubscriptionState {
    case active
    case grace
    case billingRetry
    case expired
}

enum Platform { case iOS, android, web }   // в один рядок

Імена варіантів пишуть з малої літери. Тип — з великої і в однині.

Варіанти не мають прихованих числових значень: SubscriptionState.active — це саме значення типу SubscriptionState, а не 0.

Коли тип відомий з контексту, ім'я типу можна пропустити:

Swift
var state = SubscriptionState.active
state = .grace          // тип уже відомий
C#

C#-enum — це обгортка над int, і (SubscriptionState)42 компілюється. У Swift для власних enum неіснуюче значення неможливе. Виняток — enum, імпортовані з C та Objective-C: там у рантаймі може прийти невідоме значення, і для них існує @unknown default (урок 33).

Перелічення і switch

switch по enum має бути вичерпним. Якщо перелічити всі варіанти, default не потрібен, і це перевага: додав новий варіант — компілятор покаже всі місця, які треба оновити.

Swift
func badge(for state: SubscriptionState) -> String {
    switch state {
    case .active: "PRO"
    case .grace, .billingRetry: "Проблема з оплатою"
    case .expired: "Оформити підписку"
    }
}
Порада

Уникай default у switch по власних enum. Він «ковтає» нові варіанти, і компілятор перестає попереджати.

Перебір варіантів

Протокол CaseIterable додає статичну колекцію allCases:

Swift
enum Difficulty: CaseIterable {
    case easy, normal, hard, nightmare
}

Difficulty.allCases.count          // 4
for level in Difficulty.allCases {
    print(level)
}

Компілятор генерує allCases сам, якщо варіанти не мають асоційованих значень.

Асоційовані значення

Кожен варіант може нести власні дані різних типів. Значення фіксуються в момент створення екземпляра і можуть відрізнятися між екземплярами одного варіанта.

Swift
enum PurchaseResult {
    case success(transactionID: UInt64, isTrial: Bool)
    case pending
    case userCancelled
    case failed(Error)
}

let result = PurchaseResult.success(transactionID: 2_000_000_123, isTrial: true)

Дістати значення — через зразок у switch чи if case:

Swift
switch result {
case .success(let id, let isTrial):
    print("Покупка \(id), trial: \(isTrial)")
case .pending:
    print("Чекаємо підтвердження (Ask to Buy)")
case .userCancelled:
    break
case .failed(let error):
    print("Помилка:", error)
}

// якщо всі значення прив'язуються як константи, let можна винести вперед
if case let .success(id, _) = result {
    print(id)
}

// var замість let — локальна змінна копія, яку можна змінювати
if case .failed(var error) = result {
    error = StoreError.wrapped(error)
    log(error)
}

Мітки асоційованих значень необов'язкові, але покращують читабельність.

C#

Це discriminated union / sum type. У C# такого прямого механізму немає: його емулюють ієрархією record-класів з базовим абстрактним типом або OneOf-бібліотеками. У Swift — це звичайний enum, і компілятор перевіряє вичерпність. Ти вже бачив, як це використовує StoreKit 2: Product.PurchaseResult — саме такий enum.

Сирі значення

Альтернатива асоційованим значенням — сирі значення (raw values): заздалегідь задані значення одного типу для всіх варіантів.

Swift
enum HTTPStatus: Int {
    case ok = 200
    case notFound = 404
    case serverError = 500
}

HTTPStatus.notFound.rawValue   // 404

На практиці сирий тип — найчастіше String (ключі для аналітики, JSON, конфігів) або Int (коди, порядок). Повторювати те саме сире значення у двох варіантах компілятор не дасть.

Не плутай з асоційованими значеннями: HTTPStatus.notFound.rawValue завжди 404 — це властивість варіанта, а .failed(error) несе різну помилку щоразу — це дані конкретного значення. Обидва механізми в одному enum поєднати не вийде.

Неявні сирі значення

Для цілих чисел значення рахуються від попереднього (+1), а перший без явного значення — 0. Для рядків сире значення — ім'я варіанта:

Swift
enum Priority: Int {
    case low = 10, medium = 20, high       // high == 21 — наступне після попереднього
}

enum Step: Int {
    case welcome, permissions, paywall     // 0, 1, 2 — нумерація з нуля
}

enum Screen: String {
    case onboarding, paywall, home         // "onboarding", "paywall", "home"
    case settings = "app_settings"
}

Рядкові сирі значення зручні для ключів аналітики, Remote Config і JSON.

Створення з сирого значення

Enum з сирим типом автоматично отримує failable ініціалізатор init?(rawValue:) — він повертає опціонал:

Swift
let fromConfig = "paywall"
if let screen = Screen(rawValue: fromConfig) {
    open(screen)
} else {
    print("Невідомий екран \(fromConfig)")
}
Порада

Значення з сервера чи конфіга завжди можуть бути невідомими (нова версія бекенду). Явно обробляй nil, а не роби Screen(rawValue: x)!.

Рекурсивні перелічення

Варіант може містити значення того самого enum-типу. Такий варіант позначають indirect (або весь enum), щоб компілятор зберігав дані через непрямий рівень — інакше розмір значення був би нескінченним.

Приклад — діалог у грі, де кожна репліка веде до наступної, а вибір розгалужує історію:

Swift
indirect enum Dialogue {
    case line(String, next: Dialogue)
    case choice(String, yes: Dialogue, no: Dialogue)
    case end
}

let intro = Dialogue.line("Привіт, мандрівнику!",
    next: .choice("Допоможеш нам?",
        yes: .line("Дякуємо!", next: .end),
        no: .end))

func longestPath(_ d: Dialogue) -> Int {
    switch d {
    case .end: 0
    case .line(_, let next): 1 + longestPath(next)
    case .choice(_, let yes, let no): 1 + max(longestPath(yes), longestPath(no))
    }
}

longestPath(intro)   // 3

Рекурсивні enum природно описують дерева й ланцюжки: AST, сценарії, вкладені меню, JSON.

Методи й властивості

Enum може мати методи, обчислювані властивості, ініціалізатори й реалізовувати протоколи. Збережених властивостей екземпляра в enum немає, а от статичні збережені властивості дозволені: static let defaultValue = ....

Swift
extension SubscriptionState {
    var hasAccess: Bool {
        switch self {
        case .active, .grace: true
        case .billingRetry, .expired: false
        }
    }

    mutating func expire() {
        self = .expired
    }
}
Практика
  1. Змоделюй стан екрана завантаження: idle, loading(progress: Double), loaded([String]), failed(message: String). Напиши обчислювану властивість isBusy.
  2. Зроби enum AnalyticsEvent з асоційованими значеннями (screenView(name:), purchase(productID:price:), abTestAssigned(test:variant:)) і функцію, що перетворює подію на (name: String, params: [String: String]).
  3. Зроби enum Rarity: Int, CaseIterable, реалізуй для нього Comparable через rawValue (оператор <) і відсортуй масив предметів за рідкістю. Потім прибери сирий тип і перевір: для enum без сирих значень компілятор згенерує Comparable сам за порядком варіантів.
  4. Розшир Dialogue варіантом reward(coins: Int, next: Dialogue) і функцією, що рахує максимальну кількість монет, яку можна отримати в діалозі.
