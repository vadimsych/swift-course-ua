Перелічення

Enum у Swift — це не набір іменованих чисел, як у C#, а повноцінний тип: з асоційованими значеннями, методами, протоколами й рекурсією. Мабуть, найпотужніший інструмент моделювання в мові.

У книзі: enumerations

Синтаксис

Swift
enum SubscriptionState {
    case active
    case grace
    case billingRetry
    case expired
}

enum Platform { case iOS, android, web }   // в один рядок

Імена варіантів пишуть з малої літери. Тип — з великої і в однині.

Варіанти не мають прихованих числових значень: SubscriptionState.active — це саме значення типу SubscriptionState, а не 0.

Коли тип відомий з контексту, ім'я типу можна пропустити:

Swift
var state = SubscriptionState.active
state = .grace          // тип уже відомий
C#

C#-enum — це обгортка над int, і (SubscriptionState)42 компілюється. У Swift для власних enum неіснуюче значення неможливе. Виняток — enum, імпортовані з C та Objective-C: там у рантаймі може прийти невідоме значення, і для них існує @unknown default (урок 33).

Перелічення і switch

switch по enum має бути вичерпним. Якщо перелічити всі варіанти, default не потрібен, і це перевага: додав новий варіант — компілятор покаже всі місця, які треба оновити.

Swift
func badge(for state: SubscriptionState) -> String {
    switch state {
    case .active: "PRO"
    case .grace, .billingRetry: "Проблема з оплатою"
    case .expired: "Оформити підписку"
    }
}
Порада

Уникай default у switch по власних enum. Він «ковтає» нові варіанти, і компілятор перестає попереджати.

Перебір варіантів

Протокол CaseIterable додає статичну колекцію allCases:

Swift
enum Difficulty: CaseIterable {
    case easy, normal, hard, nightmare
}

Difficulty.allCases.count          // 4
for level in Difficulty.allCases {
    print(level)
}

Компілятор генерує allCases сам, якщо варіанти не мають асоційованих значень.

Асоційовані значення

Звичайний enum — це лише вибір одного з варіантів. У Swift кожен варіант може ще й нести з собою дані, причому в кожного варіанта — свої. У C# прямого аналога немає, тому почнімо з того, як би ти зробив це там:

C#
abstract record Reward;
record Coins(int Amount) : Reward;
record Item(string Name) : Reward;
record Nothing : Reward;

У Swift те саме — один enum:

Swift
enum Reward {
    case coins(Int)        // монети — і скільки саме
    case item(String)      // предмет — і його назва
    case nothing           // нічого, даних немає
}

let r1 = Reward.coins(50)
let r2 = Reward.item("Меч")
let r3 = Reward.nothing

Дужки після назви варіанта означають «цей варіант зберігає значення такого типу». Значення задається при створенні й у кожної нагороди своє: одна дає 50 монет, інша — 200.

Дістати дані — через switch. У кожній гілці витягуєш те, що несе саме цей варіант:

Swift
func show(_ reward: Reward) {
    switch reward {
    case .coins(let amount):          // якщо це монети — поклади кількість в amount
        print("Отримано монет: \(amount)")
    case .item(let name):
        print("Отримано предмет: \(name)")
    case .nothing:
        print("Нічого")
    }
}

show(.coins(50))   // Отримано монет: 50

Компілятор перевіряє, що оброблено всі варіанти: додаси новий вид нагороди — він покаже кожен switch, який треба оновити.

Мітки асоційованих значень

Значенням можна дати імена — так створення й читання коду стають зрозумілішими:

Swift
enum PurchaseResult {
    case success(transactionID: String, isTrial: Bool)
    case userCancelled
    case failed(message: String)
}

let ok = PurchaseResult.success(transactionID: "tx_123", isTrial: true)
// без міток було б .success("tx_123", true) — і незрозуміло, що за true

Мітки необов'язкові в оголошенні, але якщо вони там є, при створенні їх писати треба. При розборі в switch можна давати змінним будь-які імена: case .success(let id, let trial).

Саме так StoreKit 2 повертає результат покупки: Product.PurchaseResult — enum з варіантами success, userCancelled і pending, де success несе дані транзакції. Такий тип не дає отримати безглузде «успіх з помилкою» чи «скасування з ID»: кожен варіант має рівно ті дані, що йому потрібні.

Окремий випадок — коли з усіх варіантів цікавить лише один. Тоді замість switch пишуть if case (урок 5):

Swift
if case .coins(let amount) = r1, amount > 10 {
    print("Багато монет: \(amount)")
}

Сирі значення

Сире значення (raw value) — це фіксоване число чи рядок, закріплене за кожним варіантом. Тип сирих значень пишуть після двокрапки:

Swift
enum HTTPStatus: Int {
    case ok = 200
    case notFound = 404
    case serverError = 500
}

let status = HTTPStatus.notFound          // тип HTTPStatus
let code = HTTPStatus.notFound.rawValue   // тип Int, значення 404

HTTPStatus.notFound — це не число, а значення типу HTTPStatus. Число з'являється лише тоді, коли явно попросиш його через .rawValue.

C# Swift
Значення enum HttpStatus.NotFound HTTPStatus.notFound
Отримати число (int)HttpStatus.NotFound HTTPStatus.notFound.rawValue
З числа в enum (HttpStatus)404 — компілюється навіть з 999 HTTPStatus(rawValue: 404) — опціонал, nil для невідомого

Що варто знати:

  • : Int — не наслідування. У enum двокрапка з Int чи String задає тип сирих значень. Після нього можна перелічити протоколи: enum Screen: String, CaseIterable, Codable.
  • Без сирого типу rawValue немає взагалі. На відміну від C#, де під кожним enum є число, у Swift enum Direction { case up, down } ні з якими числами не пов'язаний, і Direction.up.rawValue — помилка компіляції.
  • Сирі значення й асоційовані дані в одному enum поєднати не можна: сире значення фіксоване для варіанта, а асоційоване своє в кожного екземпляра.
  • Повторювати те саме сире значення у двох варіантах компілятор не дасть.

Неявні сирі значення

Не обов'язково писати значення для кожного варіанта:

Swift
enum Step: Int {
    case welcome, permissions, paywall     // 0, 1, 2 — нумерація з нуля
}

enum Priority: Int {
    case low = 10, medium = 20, high       // high == 21 — наступне після попереднього
}

enum Screen: String {
    case onboarding, paywall, home         // "onboarding", "paywall", "home" — ім'я варіанта
    case settings = "app_settings"
}

Рядкові сирі значення зручні для ключів аналітики, Remote Config і JSON.

Створення з сирого значення

Screen(rawValue:) повертає опціонал, бо рядок може не відповідати жодному варіанту:

Swift
let fromConfig = "paywall"
if let screen = Screen(rawValue: fromConfig) {
    print("Відкриваємо \(screen)")
} else {
    print("Невідомий екран \(fromConfig)")
}
Порада

Значення з сервера чи конфіга завжди можуть бути невідомими (нова версія бекенду). Явно обробляй nil, а не роби Screen(rawValue: x)!.

Порада

Окремий інструмент для наборів прапорців, як [Flags] enum у C#, — структура з протоколом OptionSet: let options: UNAuthorizationOptions = [.alert, .sound]. Детально — в уроці 29.

Рекурсивні перелічення

Рекурсивне перелічення — enum, варіант якого містить значення цього самого enum. Приклад з життя — файли й папки: папка містить файли й інші папки, ті — свої, і так далі:

Swift
enum Item {
    case file(name: String, size: Int)
    case folder(name: String, contents: [Item])   // папка містить інші Item
}

let project = Item.folder(name: "Project", contents: [
    .file(name: "README.md", size: 2),
    .folder(name: "Assets", contents: [
        .file(name: "logo.png", size: 120),
        .file(name: "icon.png", size: 40)
    ])
])

func totalSize(_ item: Item) -> Int {
    switch item {
    case .file(_, let size):
        return size
    case .folder(_, let contents):
        return contents.reduce(0) { $0 + totalSize($1) }   // заходимо всередину
    }
}

print(totalSize(project))   // 162

Функція обробляє поточний рівень і викликає сама себе для вкладених — звичайна рекурсія.

Навіщо слово indirect

Згадай C#: struct Node { int value; Node next; } не скомпілюється (CS0523). Щоб розмістити структуру в пам'яті, треба знати її розмір, а розмір Node включає Node, і так нескінченно. Там це розв'язують класом: поле стає посиланням, а об'єкт лежить окремо.

Enum у Swift — теж value type, і проблема та сама. Якщо варіант містить той самий enum напряму, потрібне слово indirect: воно каже «зберігай вкладене значення окремо, а тут тримай лише посилання».

Swift
indirect enum Chain {
    case end
    case link(Int, Chain)          // напряму — без indirect не скомпілюється
}

let list = Chain.link(1, .link(2, .link(3, .end)))   // 1 → 2 → 3 → кінець

У прикладі з папками indirect не знадобився: вкладені Item лежать у масиві, а масив і так зберігає елементи окремо. Якщо забудеш indirect там, де він потрібен, компілятор сам підкаже: «recursive enum is not marked 'indirect'».

Методи й властивості

Enum у Swift — повноцінний тип: до нього можна додати обчислювані властивості, методи, ініціалізатори й протоколи. У C# так не можна — там логіку для enum виносять в extension methods чи switch по всьому коду.

Візьмемо стани підписки, як у StoreKit:

Swift
enum SubscriptionState {
    case active          // активна
    case grace           // оплата не пройшла, але доступ ще є
    case billingRetry    // Apple пробує списати гроші, доступу вже немає
    case expired         // закінчилась

    // обчислювана властивість: рахується з поточного стану
    var hasAccess: Bool {
        switch self {
        case .active, .grace: true
        case .billingRetry, .expired: false
        }
    }

    // mutating-метод: змінює сам стан
    mutating func expire() {
        self = .expired
    }
}

var state = SubscriptionState.grace
print(state.hasAccess)   // true
state.expire()
print(state.hasAccess)   // false

Що тут відбувається:

  • self — значення, на якому викликали властивість чи метод, як this у C#. Для state.hasAccess це .grace, тож результат true.
  • mutating позначає метод, що змінює сам enum. Методи структур і enum за замовчуванням змінювати self не можуть; mutating це дозволяє. Всередині self = .expired означає «змінна, на якій викликали метод, тепер .expired». На let-константі такий метод викликати не можна.
  • Збережених властивостей екземпляра в enum немає: var lastCheck = Date() всередині enum не скомпілюється, бо значення enum — лише «який варіант». Якщо варіанту потрібні дані, їх кладуть в асоційовані значення. А от static let можна — це одне значення на весь тип.
Практика
  1. Змоделюй стан екрана завантаження: idle, loading(progress: Double), loaded([String]), failed(message: String). Напиши обчислювану властивість isBusy.
  2. Зроби enum AnalyticsEvent з асоційованими значеннями (screenView(name:), purchase(productID:price:), abTestAssigned(test:variant:)) і функцію, що перетворює подію на (name: String, params: [String: String]).
  3. Зроби enum Rarity: Int, CaseIterable, реалізуй для нього Comparable через rawValue (оператор <) і відсортуй масив предметів за рідкістю. Потім прибери сирий тип і перевір: для enum без сирих значень компілятор згенерує Comparable сам за порядком варіантів.
  4. Додай до Item варіант shortcut(name: String, target: Item) і онови totalSize, щоб ярлики не враховувались у розмірі. Чи знадобиться indirect?
