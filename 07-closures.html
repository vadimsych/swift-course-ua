Замикання

Лямбди Swift для C#-розробника: як вони записуються (від повної форми до найкоротшої), trailing closures, захоплення змінних, чому замикання — reference type, @escaping і @autoclosure.

У книзі: closures

Що ти вже знаєш з C

Лямбда x => x * 2, делегати Func<>/Action<>, захоплення змінних у display class — усе це в Swift є і називається замиканнями. Причому в Swift немає різниці між «методом» і «лямбдою» як значеннями: іменована функція, вкладена функція й вираз у фігурних дужках однаково можна покласти в змінну чи передати аргументом. Відрізняються вони лише тим, чи мають ім'я і чи захоплюють щось з оточення.

Синтаксис: від довгої форми до короткої

Візьмемо функцію вищого порядку — так називають функцію, що приймає іншу функцію як параметр (як Where у LINQ). Напишемо свою: повторювач спроб.

Swift
func retry(_ times: Int, _ attempt: (Int) -> Bool) -> Bool {
    for n in 1...times where attempt(n) { return true }
    return false
}

Простими словами: «спробуй до times разів; якщо хоч раз вийшло — поверни true». attempt — що саме пробувати: функція, яка отримує номер спроби і повертає, чи вдалося. У C# це був би параметр Func<int, bool> attempt.

Нехай є функція connect(_ n: Int) -> Bool, що пробує під'єднатися до сервера. Передати її в retry можна шістьма способами, і всі вони роблять одне й те саме:

1. Повна форма — розписано все: параметр, його тип, тип результату. Слово in відділяє заголовок від тіла.

Swift
retry(3, { (n: Int) -> Bool in
    return connect(n)
})

2. Без типів — Swift і так знає з оголошення retry, що тут (Int) -> Bool:

Swift
retry(3, { n in return connect(n) })

3. Без return — у тілі один вираз, і його результат повертається сам:

Swift
retry(3, { n in connect(n) })

4. Без імені параметра. Якщо список параметрів не писати, Swift дає їм автоматичні імена: $0 — перший параметр, $1 — другий і так далі.

Swift
retry(3, { connect($0) })

5. Замикання після дужок — якщо воно останній аргумент, його можна винести за круглі дужки (детально — нижче):

Swift
retry(3) { connect($0) }

6. Сама функція — connect уже має потрібний тип (Int) -> Bool, тож замикання взагалі не потрібне:

Swift
retry(3, connect)

На практиці найчастіше трапляються форми 4–6: scores.filter { $0 > 100 }, items.map { $0.name }, Button("OK") { ... }. Повну форму пишуть, коли замикання довге або типи неочевидні.

Swift C#
{ (n: Int) -> Bool in return connect(n) } (int n) => { return Connect(n); }
{ n in connect(n) } n => Connect(n)
{ connect($0) } немає — ім'я параметра в C# пишеш завжди
retry(3, connect) Retry(3, Connect) — method group

Ще кілька деталей:

  • Без контексту { n in n * 2 } не скомпілюється: компілятор не знає, який тип у n. Типи виводяться саме з функції, якій передаєш замикання.
  • Оператор — теж функція: scores.sorted(by: >) передає > як «порівняй два числа».
  • Коли замикання довге або вкладене в інше, давай параметрам нормальні імена замість $0 — інакше незрозуміло, на що вказує $0.

Хвостові замикання (trailing closures)

Усталеного українського терміна немає. Розробники кажуть «trailing closure», у курсі — «хвостове замикання». Суть: замикання, що є останнім аргументом, пишуть після круглих дужок, а не всередині них:

Swift
retry(3, { connect($0) })   // звичайно
retry(3) { connect($0) }    // хвостове замикання

Якщо замикання — єдиний аргумент, дужки зникають зовсім: items.forEach { print($0) }. Якщо замикань наприкінці кілька, перше пишуть без мітки, а наступні — з мітками:

Swift
func fade(duration: Double,
          step: (Double) -> Void,
          completion: () -> Void) { }

fade(duration: 0.3) { alpha in
    print("Прозорість", alpha)
} completion: {
    print("Анімацію завершено")
}

На хвостових замиканнях побудований синтаксис SwiftUI: VStack { ... }, Button("OK") { ... }, .task { ... }.

Захоплення змінних

Замикання бачить змінні з місця створення і тримає їх стільки, скільки живе саме. Практичний приклад — обмежувач частоти подій, щоб аналітика не отримувала той самий тап частіше, ніж раз на пів секунди:

Swift
import Foundation

func throttled(interval: TimeInterval, _ action: @escaping () -> Void) -> () -> Void {
    var lastRun = Date.distantPast          // захоплена змінна живе разом із замиканням
    return {
        let now = Date()
        guard now.timeIntervalSince(lastRun) >= interval else { return }
        lastRun = now                       // замикання змінює захоплену змінну
        action()
    }
}

let trackTap = throttled(interval: 0.5) { print("tap sent") }
trackTap()   // tap sent
trackTap()   // нічого: з минулого виклику минуло менше 0.5 с

Функція throttled давно завершилась, а lastRun живе в замиканні й оновлюється між викликами.

Захоплюється сама змінна, а не копія її значення в момент створення. Те, що Int — структура, нічого не змінює:

Swift
var multiplier = 2
let scale = { (x: Int) in x * multiplier }
multiplier = 10
print(scale(3))     // 30, а не 6

У C# буде так само — 30. Компілятор C# переносить захоплену змінну в прихований клас, і лямбда та навколишній код працюють з одним і тим самим полем.

Щоб «заморозити» значення на момент створення, його вказують у списку захоплення (capture list) — квадратних дужках на початку замикання:

Swift
var rate = 2
let frozen = { [rate] (x: Int) in x * rate }   // rate скопійовано зараз
rate = 10
print(frozen(3))    // 6
C# Swift
Захопити змінну x => x * m → бачить зміни { x in x * m } → бачить зміни
Захопити значення зараз var copy = m; x => x * copy { [m] x in x * m }

Бонус порівняно з C#: змінна циклу for-in на кожній ітерації нова, тож лямбди, створені в циклі, не «бачать» одне й те саме значення.

Замикання — reference type

Якщо одне замикання покласти в кілька місць, усі вони вказують на той самий об'єкт із тим самим захопленим станом:

Swift
let trackSwipe = throttled(interval: 0.5) { print("swipe sent") }

var handlers: [String: () -> Void] = [:]
handlers["left"] = trackSwipe
handlers["right"] = trackSwipe      // те саме замикання, спільний lastRun

handlers["left"]?()                 // swipe sent
handlers["right"]?()                // нічого: вікно 0.5 с спільне

Звідки тут ?(): звертання до словника повертає опціонал, бо ключа може не бути. Тому handlers["left"] має тип (() -> Void)? — «функція або nil». ?() означає «якщо функція є — виклич, якщо nil — нічого не роби». Те саме, що handler?.Invoke() у C#.

Звідси й головний ризик — цикли сильних посилань, коли об'єкт тримає замикання, а замикання тримає об'єкт. Розберемо нижче й детальніше — в уроці про ARC.

Escaping-замикання

Коли ти передаєш замикання у функцію, можливі два сценарії:

  1. Функція викликає його одразу і ніде не зберігає. Так працюють map, filter, sorted, forEach.
  2. Функція зберігає його, щоб викликати пізніше — у властивості, масиві, черзі, після мережевого запиту. Замикання «втікає» з функції й живе далі. Це й називається escaping.

Для другого сценарію параметр позначають @escaping:

Swift
final class Button {
    private var onTap: (() -> Void)?

    func setAction(_ action: @escaping () -> Void) {
        onTap = action          // зберегли, викличемо, коли користувач натисне
    }

    func simulateTap() {
        onTap?()
    }
}

setAction нічого не викликає — лише кладе замикання у властивість. Без @escaping рядок onTap = action дасть помилку компіляції («assigning non-escaping parameter to an @escaping closure»), і Xcode запропонує дописати слово.

Навіщо Swift це розрізняє:

  • Швидкість. Замикання без @escaping компілятор вважає тимчасовим і може зберігати дешевше. Якби таке замикання поклали у властивість, воно пережило б те, на що посилається. Тому компілятор це забороняє.
  • Пам'ять. Збережене замикання тримає все, що захопило, включно з об'єктом. Слово @escaping в оголошенні — сигнал: «тут замикання житиме довго, подумай про цикли посилань».
C#

У C# такої позначки немає: будь-яку лямбду можна зберегти в поле чи подію. У Swift за замовчуванням замикання не escaping, і якщо ти зберігаєш його, це треба сказати явно.

Цикл посилань і self

Найчастіше збережене замикання тримає об'єкт, який сам (прямо чи через інші об'єкти) тримає це замикання:

Swift
final class CartBadge {
    var itemCount = 0
    let button = Button()

    func connect() {
        button.setAction { self.itemCount += 1 }
    }
}
CartBadge → button → збережене замикання
    ↑                       │
    └───────────────────────┘

CartBadge тримає кнопку, кнопка тримає замикання, замикання використовує self.itemCount, тобто тримає CartBadge. У Swift немає збирача сміття, а лічильник посилань кожного з трьох ніколи не впаде до нуля. Навіть коли екран закриють, усе коло лишиться в пам'яті — це витік. У C# GC прибрав би таке недосяжне коло, а в Swift ні.

Правильно так:

Swift
button.setAction { [weak self] in self?.itemCount += 1 }

[weak self] означає: «тримай CartBadge слабко, не збільшуй його лічильник». Слабким робиться посилання на об'єкт, а не властивість: itemCount — просто число всередині CartBadge. Коли CartBadge звільниться, self у замиканні стане nil, і self?.itemCount += 1 нічого не зробить.

Навіщо писати self.. self.itemCount і itemCount всередині класу — одне й те саме, як this.itemCount і itemCount у C#. Обидва записи захоплюють об'єкт. Але в escaping-замиканні класу Swift вимагає написати self. явно (або [self] у списку захоплення), інакше помилка компіляції. Це навмисна позначка: щоб захоплення об'єкта не було непомітним.

Запис Що з пам'яттю
{ self.itemCount += 1 } сильне захоплення
{ [self] in itemCount += 1 } сильне захоплення
{ [weak self] in self?.itemCount += 1 } слабке захоплення, циклу немає

self. можна не писати в non-escaping замиканнях (на кшталт forEach) і в коді структур та enum: циклу там не буде. Але змінити self структури з escaping-замикання не можна — коли воно виконається, метод уже давно завершиться.

Порада

Як знайти такий витік: додай deinit { print("CartBadge звільнено") } і закрий екран. Немає повідомлення — десь цикл. Наочніше — Xcode → Debug Memory Graph: він показує живі об'єкти й стрілки посилань між ними.

Autoclosures

Звичайний аргумент функції обчислюється до виклику. Через це навіть «вимкнене» логування може робити дорогу роботу:

Swift
var isLoggingEnabled = false

func buildReport() -> String {
    print("⚠️ buildReport викликано")
    return "дані"
}

func logPlain(_ message: String) {
    if isLoggingEnabled { print(message) }
}

logPlain("Звіт: \(buildReport())")

Порядок виконання:

  1. Swift обчислює аргумент: викликає buildReport() і склеює рядок.
  2. Заходить у logPlain з готовим рядком.
  3. Логування вимкнене, print не виконується.

print не спрацював, але buildReport() уже відпрацював на кроці 1 — даремно.

Щоб обчислення відбувалося лише за потреби, можна передати замикання, яке вміє зробити рядок:

Swift
func logLazy(_ message: () -> String) {
    if isLoggingEnabled { print(message()) }
}

logLazy { "Звіт: \(buildReport())" }      // buildReport() не викличеться

@autoclosure робить те саме, але фігурні дужки на виклику дописує компілятор:

Swift
func logAuto(_ message: @autoclosure () -> String) {
    if isLoggingEnabled { print(message()) }
}

logAuto("Звіт: \(buildReport())")         // виглядає як рядок, але buildReport() не викличеться
Оголошення Виклик Коли обчислюється аргумент
_ message: String log("…") завжди, до входу у функцію
_ message: () -> String log { "…" } лише якщо функція викличе message()
_ message: @autoclosure () -> String log("…") лише якщо функція викличе message()

Так влаштовані ??, &&, || і assert: у savedName ?? loadDefaultName() функція loadDefaultName() викликається, лише якщо savedName дорівнює nil.

C#

@autoclosure — це параметр Func<string>, але без () => на місці виклику.

Пастка

На виклику logAuto(buildReport()) не видно, що buildReport() може не виконатися. У власних API краще явне замикання з { }: так відкладене виконання помітне.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що з цього можна покласти в змінну типу (Int) -> Int?

Іменовані функції, вкладені функції й вирази в { } — усе це замикання, і всі вони є значеннями.

2. Що означає $0 у scores.filter { $0 > 100 }?

Якщо параметри не названо, Swift дає їм імена $0, $1…

3. Який із цих записів не еквівалентне іншим трьом?

connect(3) одразу викликає функцію й передає її результат (Bool), а не саму функцію.

4. Що передає scores.sorted(by: >)?

Оператор — теж функція, тож його можна передати як значення.

5. Що таке хвостове замикання (trailing closure)?

Якщо воно єдиний аргумент, дужки зникають зовсім: items.forEach { print($0) }.

6. Що надрукує цей код?

Swift
var multiplier = 2
let scale = { (x: Int) in x * multiplier }
multiplier = 10
print(scale(3))

Замикання захоплює саму змінну, а не копію значення, тож бачить зміну.

7. Що надрукує цей код?

Swift
var rate = 2
let frozen = { [rate] (x: Int) in x * rate }
rate = 10
print(frozen(3))

Значення зі списку захоплення [rate] копіюється в момент створення замикання.

8. Чому handlers["left"]?() має ??

?() означає «якщо функція є — виклич, якщо nil — нічого не роби».

9. Коли параметр-замикання треба позначити @escaping?

Без @escaping збереження замикання у властивість чи масив — помилка компіляції.

10. Що змінює [weak self] у замиканні?

Коли об'єкт звільниться, self у замиканні стане nil. Так розривають цикли посилань.

11. Яке твердження неправильне?

Обидва записи звертаються до того самого об'єкта. Вимога писати self. — лише видима позначка захоплення.

12. Що надрукує цей код?

Swift
func run() {
    var calls = 0
    func expensive() -> String { calls += 1; return "x" }
    func logLazy(_ m: @autoclosure () -> String) {
        if Bool.random() && false { print(m()) }
    }
    logLazy(expensive())
    print(calls)
}
run()

@autoclosure загортає аргумент у замикання. Функція його не викликала, тож expensive() не виконалась.

Практика
  1. Відсортуй масив гравців (name: String, score: Int) за спаданням очок, а при рівності — за іменем. Спробуй кожну форму з таблиці.
  2. Напиши func debounce(_ action: @escaping () -> Void) -> () -> Void, що запускає action лише на кожен третій виклик.
  3. Поясни, чому sorted(by:) не потребує @escaping, а DispatchQueue.main.async потребує.
  4. Реалізуй власний func orElse<T>(_ value: T?, _ fallback: @autoclosure () -> T) -> T.
