Довідник (за потреби) · урок 31

Довідник: типи

Огляд усіх видів типів у Swift: іменовані й складені, функціональні типи і обмеження non-escaping замикань, опціонали, композиції протоколів, some/any, метатипи, Any, Self, списки успадкування і виведення типів.

У книзі: types

Два види типів

  • Іменовані — мають ім'я: класи, структури, enum, протоколи, а також усі типи стандартної бібліотеки (Int, String, Array…). Їх можна розширювати.
  • Складені — описуються структурою, а не іменем: функціональні (Int) -> String і кортежі (Int, String). Розширювати їх не можна.

Дужки навколо типу нічого не змінюють: (Int) — це просто Int.

Анотація типу

: Тип після імені змінної чи параметра. Перед типом можуть стояти атрибути (@escaping, @Sendable, @MainActor) і модифікатори (inout, borrowing, consuming).

Swift
func run(_ job: @escaping @Sendable () async -> Void) { }

Ідентифікатор типу

Ім'я іменованого типу, псевдоніма або generic-параметра, з аргументами в кутових дужках і крапками для вкладених типів: Dictionary<String, Int>, Paywall.Option, Array<Element>.Index.

Кортежі

Список типів через кому в дужках, елементи можуть мати імена: (code: Int, message: String). Імена — частина типу: значення з іншими мітками не присвоїш ((x: 1, y: 2) у змінну типу (a: Int, b: Int)), а кортеж без міток — можна. Порожній кортеж () — це Void. Кортежу з одного елемента не існує: (Int) — просто Int.

Функціональні типи

(параметри) -> результат, з можливими async, throws або throws(E) перед стрілкою:

Swift
let handler: (String, Int) async throws -> Bool
let simple: () -> Void
let curried: (Int) -> (Int) -> Int
  • Мітки аргументів у тип не входять: func f(x: Int) і func g(y: Int) мають однаковий тип (Int) -> Int.
  • (Int) -> (Int) -> Int читається як «функція, що повертає функцію».
  • Не-throwing функцію можна передати туди, де очікують throwing, а синхронну — туди, де очікують async. Навпаки — ні.

Обмеження non-escaping замикань

Параметр-замикання без @escaping не може «вийти» за межі функції: його не можна зберегти у властивість чи масив. Детально — урок 7.

Масиви

[Element] — скорочення для Array<Element>. Багатовимірні масиви — масиви масивів: [[Int]]. Для масивів фіксованого розміру в стандартній бібліотеці є InlineArray<N, Element> з цілочисельним generic-параметром (урок 36).

Словники

[Key: Value] — скорочення для Dictionary<Key, Value>. Key має бути Hashable.

Опціонали

T? — скорочення для Optional<T> (пробіл перед ? не допускається; для складних типів — дужки: (Int, Int)?), enum з варіантами none і some(T). Будь-яка змінна опціонального типу без значення має nil. Постфіксний ! примусово розгортає, ? — запускає ланцюжок.

Неявно розгорнуті опціонали

T! — той самий Optional<T>, але компілятор дозволяє використовувати значення без явного розгортання, вставляючи ! автоматично там, де потрібен T. Якщо значення nil — крах. Позначка ! — властивість оголошення, а не окремий тип: [Int!] записати не можна.

Композиції протоколів

P & Q — значення, що відповідає обом протоколам. Можна додати один клас: UIViewController & Trackable. Композицію часто дають псевдоніму: typealias Codable = Decodable & Encodable — саме так визначено Codable.

Непрозорі типи

some P — один конкретний тип, що відповідає P, відомий компілятору, але прихований від користувача. Дозволений у результаті функцій, сабскриптів і обчислюваних властивостей, у типах параметрів (кожен some-параметр — окремий неявний generic-параметр) і в збережених властивостях з ініціалізатором. Усі шляхи повернення мусять давати один тип. Не дозволений у вимогах протоколів, у variadic-параметрі та у функціональних типах параметрів; метод класу з some-результатом не можна перевизначити. Урок 25.

Упаковані протокольні типи

any P — контейнер для будь-якого значення, що відповідає P. Тип значення може відрізнятися між екземплярами й змінюватися з часом; за це платять зберіганням у коробці й динамічними викликами. any Any і any AnyObject нічого не змінюють. Для протоколів без асоційованих типів і Self-вимог слово any у старому коді могло бути пропущене, але для нового коду його пишуть завжди.

Метатипи

Метатип — тип самого типу. Для класу, структури чи enum T метатип — T.Type, для протоколу P — P.Protocol (сам протокол) або any P.Type (метатип будь-якого типу, що відповідає P).

Swift
let intType: Int.Type = Int.self
let value = intType.init("42")             // Optional(42)

class Screen { required init() {} }
final class Paywall: Screen { }

func make(_ type: Screen.Type) -> Screen {
    type.init()                            // потрібен required init
}

let screen = make(Paywall.self)
type(of: screen)                           // Paywall.self — динамічний тип
  • T.self — значення-метатип (як typeof(T) у C#).
  • type(of: value) — динамічний тип у рантаймі (як GetType()).
  • Ініціалізатор через метатип вимагає required або final-класу.

Тип Any

Any — тип, якому відповідають усі типи, включно з функціями й опціоналами. AnyObject — протокол, якому відповідають усі класи. Урок 20.

Тип Self

Self — поточний тип в контексті, де його вжито:

  • у протоколі — тип, що реалізує протокол;
  • у структурі, класі чи enum — сам тип (або у класі — динамічний тип екземпляра);
  • в результаті методу класу -> Self — гарантія, що метод повертає екземпляр того самого підкласу.
Swift
class Builder {
    required init() {}
    func copy() -> Self { Self() }   // підклас поверне свій тип
}

У членах класу Self дозволений лише як тип результату методу, тип результату read-only сабскрипта, тип read-only обчислюваної властивості та всередині тіла методу. Self.member — те саме, що type(of: self).member. У вкладених типах Self означає найближчий охопний тип.

Список успадкування

Після двокрапки в оголошенні типу: суперклас (для класів — першим, максимум один), протоколи, а в enum — сирий тип першим. Для протоколів — успадковані протоколи, AnyObject чи суперклас. Придушені неявні відповідності пишуться з тильдою: ~Copyable, ~Sendable.

Виведення типів

Swift виводить типи двонаправлено: з ініціалізаторів до змінних і з очікуваного типу до літералів і замикань. Інформація може йти й «згори вниз»:

Swift
let a = 3            // Int — тип за замовчуванням для цілого літерала
let b: Double = 3    // літерал стає Double з очікуваного типу
let c = 3 + 0.5      // Double — літерали без типу підлаштовуються один під одного
let names = ["a", "b"].map { $0.uppercased() }   // замикання отримує тип з map

Виведення працює в межах одного виразу чи оголошення. Через це надто складні вирази з багатьма перевантаженими операторами й літералами іноді компілюються довго або спричиняють помилку «unable to type-check in reasonable time». Розв'язок — додати анотацію типу або розбити вираз.

Практика
  1. Напиши функцію func makeAll(_ types: [Screen.Type]) -> [Screen], що створює екземпляри з масиву метатипів.
  2. Запиши тип функції, що приймає рядок і повертає асинхронну throwing-функцію без параметрів, яка повертає Int.
  3. Знайди в стандартній бібліотеці, як визначено Codable, і поясни запис.
  4. Створи вираз, на якому компілятор довго виводить тип, і виправ його анотацією.
