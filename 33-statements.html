Довідник (за потреби) · урок 33

Довідник: інструкції

Цикли, розгалуження, мітки, передача керування, defer, do, директиви компілятора (#if, #sourceLocation, #warning) і умова доступності — з точними правилами, які в першій частині курсу лише згадувалися.

У книзі: statements

Інструкції бувають прості (вирази й оголошення), інструкції керування і директиви компілятора. Інструкції розділяються переносом рядка або ;.

Цикли

for-in

Swift
for зразок in послідовність where умова {
    інструкції
}
  • Послідовність — будь-яке значення, що відповідає Sequence. Цикл викликає makeIterator() і далі next(), поки той не поверне nil.
  • Зліва може бути будь-який зразок: for (key, value) in dict, for case let .coins(n) in rewards, for case let x? in optionals.
  • where фільтрує ітерації.
  • Для асинхронних послідовностей — for await / for try await.

while

Перевіряє умову перед кожною ітерацією. Умова — це список умов через кому, кожна з яких може бути булевим виразом, прив'язуванням опціоналу (let x = ...), зразком (case .a = x) або перевіркою доступності.

Swift
while let job = queue.popFirst(), !Task.isCancelled {
    process(job)
}

repeat-while

Тіло виконується хоча б раз, умова — булевий вираз наприкінці.

Розгалуження

if

Список умов, як у while; гілки else if і else. Константи, прив'язані в умові, доступні лише в гілці, де умова виконалась.

guard

Swift
guard список-умов else {
    // мусить вийти з області: return, break, continue, throw
    // або викликати функцію, що повертає Never
}

Прив'язані константи доступні після guard до кінця області видимості.

switch

Swift
switch значення {
case зразок1, зразок2 where умова:
    інструкції
case let .x(a):
    інструкції
@unknown default:
    інструкції
}
  • Порівняння зі зразками — через оператор ~= (його можна перевантажити для власних типів, щоб case розумів, наприклад, діапазони дат).
  • Кожна гілка мусить містити хоча б одну інструкцію.
  • Гілки розглядаються згори вниз, виконується перша відповідна; неявного переходу в наступну немає.
  • switch має бути вичерпним.
  • Якщо в одній гілці кілька зразків, усі вони мусять прив'язувати ті самі імена тих самих типів.
  • default може бути лише один, і він стоїть останнім.

Перелічення, які можуть розширитися

Нові версії iOS можуть додавати варіанти до системних enum. Тому switch по такому enum вимагає гілку за замовчуванням. Пиши @unknown default: він обробить майбутні варіанти, а компілятор усе одно попередить, якщо ти пропустив уже відомий.

Swift
switch UIDevice.current.userInterfaceIdiom {
case .phone: layoutPhone()
case .pad: layoutPad()
case .mac, .tv, .carPlay, .vision, .unspecified: layoutDefault()
@unknown default: layoutDefault()
}

Звичайний default для таких enum приховав би пропущені варіанти.

Інструкції з мітками

Мітка ім'я: перед циклом, if, switch або do дозволяє звертатися до цієї інструкції з break або continue:

Swift
validation: do {
    guard !email.isEmpty else { break validation }
    guard email.contains("@") else { break validation }
    submit()
}

continue з міткою працює лише для циклів. Мітки мають бути унікальними в межах вкладеності.

Передача керування

  • break — завершує цикл чи switch; з міткою — будь-яку інструкцію з цією міткою. Без мітки з if чи do вийти не можна.
  • continue — переходить до наступної ітерації циклу (найближчого або з міткою).
  • fallthrough — у switch переходить у тіло наступної гілки без перевірки її умови. Не можна переходити в гілку, що прив'язує значення, і не можна використовувати в останній гілці.
  • return — виходить з функції чи методу, повертаючи значення або нічого. В ініціалізаторі — лише return без значення (або return nil у failable).
  • throw — кидає помилку. Значення має відповідати Error (або типу з throws(E)).

defer

Swift
defer {
    інструкції
}
  • Виконується при виході з поточної області видимості будь-яким шляхом.
  • Кілька defer — у зворотному порядку.
  • У defer не можна виходити з області (return, break, кидати помилку назовні), але можна викликати await в асинхронній функції.
  • defer наприкінці області виконується одразу, тож писати його останньою інструкцією немає сенсу.

do

do { } створює нову область видимості, з необов'язковими гілками catch:

Swift
do throws(NetworkError) {
    try await request()
} catch .timeout {
    retry()
} catch {
    show(error)        // error: NetworkError
}
  • Без catch — просто блок для обмеження видимості й часу життя змінних (аналог { } у C#).
  • catch без зразка прив'язує помилку до неявної константи error; якщо в одній гілці кілька зразків, вони прив'язують однакові імена однакових типів.
  • Якщо catch-гілки не вичерпні, необроблені помилки поширюються далі, а на верхньому рівні програми необроблена помилка зупиняє її.
  • do throws(E) задає тип помилок явно. Без нього тип виводиться: якщо тіло нічого не кидає — блок не кидає; якщо всі try кидають один конкретний тип — блок кидає саме його; інакше — any Error.

Директиви компілятора

Умовна компіляція

Swift
#if DEBUG
let apiURL = URL(string: "https://staging.example.com")!
#elseif BETA
let apiURL = URL(string: "https://beta.example.com")!
#else
let apiURL = URL(string: "https://api.example.com")!
#endif

Умови можуть бути:

  • прапорці компіляції (DEBUG, власні з Active Compilation Conditions / -D);
  • os(iOS), os(macOS), os(watchOS), os(tvOS), os(visionOS), os(Linux), os(Windows);
  • arch(arm64), arch(x86_64) тощо;
  • swift(>=6.0), compiler(>=6.2) — версія режиму мови і компілятора;
  • canImport(UIKit) — чи доступний модуль;
  • targetEnvironment(simulator), targetEnvironment(macCatalyst);
  • hasFeature(...), hasAttribute(...) — перевірка підтримки можливостей мови;
  • комбінації через !, &&, || і дужки.

Також можна писати просто true чи false. Між оператором порівняння й версією в swift(>=6.0) пробілу немає. canImport(X) лише перевіряє доступність модуля, а імпортувати його все одно треба окремо.

Код у неактивній гілці не компілюється, але має бути синтаксично правильним.

C#

Те саме, що #if DEBUG у C#. Відмінність — набір вбудованих перевірок платформи, архітектури й доступності модулів.

Керування номером рядка

#sourceLocation(file: "Generated.swift", line: 1) змінює ім'я файлу й номер рядка, які компілятор використовує в діагностиці. #sourceLocation() повертає справжні значення. Застосовується генераторами коду.

Діагностичні директиви

Swift
#warning("Тимчасова заглушка ціни")
#error("Цей модуль не підтримує watchOS")

Видають попередження чи помилку компіляції з повідомленням. Зручно в поєднанні з #if. Зі Swift 5.9 це макроси стандартної бібліотеки, а не окремі директиви.

Умова доступності

Swift
if #available(iOS 18, macOS 15, *) { ... }
guard #available(iOS 17, *) else { return }
if #unavailable(iOS 16) { ... }
  • Перелічуються платформи з мінімальними версіями; * обов'язкова в #available і означає «на інших платформах — мінімальна версія таргета».
  • Компілятор використовує цю інформацію, щоб дозволити виклики API, позначених @available з новішою версією, усередині відповідної гілки.
  • #available не поєднується з іншими умовами через || чи && — лише через кому в списку умов; заперечують його через #unavailable, у якому * не пишуть.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що надрукує цей код?

Swift
let values: [Int?] = [1, nil, 3, 4]
for case let x? in values where x > 1 {
    print(x)
}

Зразок let x? пропускає nil і розгортає значення, а where відкидає 1.

2. Що надрукує цей код?

Swift
func run() {
    var queue = [1, 2, 3]
    while let x = queue.popLast(), x > 1 {
        print(x)
    }
}
run()

Умова while — список умов: цикл зупиняється, коли x > 1 стає хибним.

3. Що надрукує цей код?

Swift
func run() {
    var i = 10
    repeat {
        print(i)
        i += 1
    } while i < 3
}
run()

Тіло repeat-while виконується хоча б раз, умова перевіряється в кінці.

4. Чому тут помилка компіляції?

Swift
func show(_ x: Int?) {
    guard let v = x else {
        print("nil")
    }
    print(v)
}
show(1)

Після guard компілятор гарантує, що умова виконалась, тому else мусить завершити область.

5. Що надрукує цей код?

Swift
let n = 5
switch n {
case 1...5: print("low")
case 5...10: print("high")
default: print("other")
}

Гілки перевіряються згори вниз, виконується лише перша відповідна, без неявного переходу.

6. Що надрукує цей код?

Swift
struct Even {}
func ~= (_: Even, value: Int) -> Bool { value % 2 == 0 }

switch 4 {
case Even(): print("even")
default: print("odd")
}

case порівнює зразок через оператор ~=, тож його можна перевантажити для свого типу.

7. Чим @unknown default кращий за звичайний default у switch по системному enum?

Звичайний default мовчки приховав би варіанти, які ти забув обробити.

8. Що надрукує цей код?

Swift
outer: for i in 1...3 {
    for j in 1...3 {
        if j == 2 { continue outer }
        if i == 3 { break outer }
        print(i, j)
    }
}

continue outer переходить до наступного i, а break outer завершує зовнішній цикл.

9. Що надрукує цей код?

Swift
switch 1 {
case 1:
    print("one")
    fallthrough
case 2:
    print("two")
default:
    print("other")
}

fallthrough переходить лише в тіло наступної гілки, не перевіряючи її умову.

10. Чому тут помилка компіляції?

Swift
let flag = true
if flag {
    print("start")
    break
}

Щоб вийти з if чи do через break, потрібна мітка.

11. Що надрукує цей код?

Swift
func run() {
    defer { print("1") }
    defer { print("2") }
    print("body")
}
run()

defer виконується при виході з області, кілька defer — у зворотному порядку.

12. Що надрукує цей код?

Swift
func run() {
    if true {
        defer { print("a") }
        print("b")
    }
    print("c")
}
run()

defer прив'язаний до поточної області — тут до тіла if, а не до всієї функції.

13. Що надрукує цей код?

Swift
enum NetError: Error { case timeout, offline }
func request() throws(NetError) { throw .offline }

do throws(NetError) {
    try request()
} catch .timeout {
    print("retry")
} catch {
    print("other: \(error)")
}

У do throws(NetError) помилка має тип NetError, тож можна зіставляти варіанти; .offline потрапляє в загальний catch з неявною error.

14. Що надрукує цей код?

Swift
#if false
print("a")
#else
print("b")
#endif

Умовою #if може бути true чи false; неактивна гілка не компілюється.

15. Яке твердження неправильне?

canImport лише перевіряє доступність модуля, import все одно пишуть окремо.

16. Що станеться при збиранні цього коду?

Swift
#error("Not supported")
print("ok")

#error зупиняє компіляцію з вказаним повідомленням; #warning дав би лише попередження.

17. Чому тут помилка компіляції?

Swift
let ready = true
if #available(macOS 10.15, *) && ready {
    print("new")
}

#available дозволений лише як окрема умова в списку умов if, guard чи while.

18. Як правильно записати перевірку «версія нижча за iOS 16»?

Заперечення — #unavailable, і * у ньому не пишуть.

Практика
  1. Напиши switch по UIUserInterfaceStyle з @unknown default і перевір, що буде, якщо прибрати один з відомих варіантів.
  2. Перевантаж оператор ~= так, щоб у switch по Int можна було писати case isEven: з функцією-предикатом.
  3. Налаштуй у Xcode власний прапорець STAGING і використай його в #if.
  4. Використай do з міткою і break для валідації форми без вкладених if.
