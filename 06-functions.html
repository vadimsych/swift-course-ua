Мова крок за кроком · урок 06

Функції

Оголошення й виклик, мітки аргументів, значення за замовчуванням, variadic і inout параметри, функціональні типи та вкладені функції.

У книзі: functions

Оголошення й виклик

Swift
func discountedPrice(price: Double, percent: Double) -> Double {
    let result = price * (1 - percent / 100)
    return result
}

print(discountedPrice(price: 199, percent: 25))

Тип результату пишеться після ->. Ім'я параметра в Swift за замовчуванням є й міткою аргументу, тому під час виклику мітку писати обов'язково: discountedPrice(price:percent:). Так і посилаються на функції в документації та коді — разом з мітками.

Параметри й результат

Без параметрів

Swift
func currentSeason() -> String { "Зима" }

Кілька параметрів

Swift
func damage(base: Int, multiplier: Double) -> Int {
    Int(Double(base) * multiplier)
}
damage(base: 20, multiplier: 1.5)

Функції з однаковими іменами, але різними мітками чи типами параметрів — різні перевантаження, як у C#.

Без результату

Функція без -> нічого не повертає — це аналог void у C#:

Swift
func log(_ message: String) {      // як void Log(string message)
    print("[LOG]", message)
}

Формально Swift називає цей «порожній результат» типом Void, але думати про нього можна просто як про void.

Значення треба повернути на кожному шляху

Якщо в сигнатурі є -> Тип, кожен можливий шлях виконання мусить закінчитися return. Інакше помилка компіляції — як not all code paths return a value у C#:

Swift
func discount(for level: Int) -> Int {
    if level > 10 {
        return 20
    }
    return 0          // без цього рядка — помилка: а що повертати для level <= 10?
}

Попередження про невикористаний результат

Якщо функція повертає значення, а ти його проігнорував, Swift покаже попередження: раз функція щось повертає, мабуть, це варто перевірити.

Swift
func save() -> Bool { true }       // true, якщо збереглося
save()                             // ⚠️ результат не використано

Буває, що результат — лише бонус і ігнорувати його нормально. Тоді функцію позначають @discardableResult, і попередження зникає:

Swift
@discardableResult
func saveSilently() -> Bool { true }

saveSilently()                      // без попередження
if !saveSilently() { print("Не збереглося") }   // перевірити все одно можна

У стандартній бібліотеці так позначено, наприклад, removeLast(): він повертає видалений елемент, але найчастіше цей елемент не потрібен.

Кілька результатів через кортеж

Swift
func splitDuration(_ seconds: Int) -> (minutes: Int, seconds: Int) {
    (seconds / 60, seconds % 60)
}

let d = splitDuration(135)
print("\(d.minutes):\(d.seconds)")   // 2:15

Опціональний кортеж

Коли результат може бути відсутнім, повертають опціональний кортеж:

Swift
import Foundation

func parseCoordinate(_ text: String) -> (lat: Double, lon: Double)? {
    let parts = text.split(separator: ",")
    guard parts.count == 2,
          let lat = Double(parts[0].trimmingCharacters(in: .whitespaces)),
          let lon = Double(parts[1].trimmingCharacters(in: .whitespaces))
    else { return nil }
    return (lat, lon)
}

if let kyiv = parseCoordinate("50.45, 30.52") {
    print(kyiv.lat, kyiv.lon)
}

Зверни увагу, де стоїть ?: тут опціональний увесь результат — або є обидві координати, або немає нічого. Тип (lat: Double?, lon: Double?) описував би інше: кожна координата могла б бути відсутньою окремо.

Неявний return

Якщо тіло функції — рівно один вираз, його значення повертається само, return можна не писати:

Swift
func isAdult(age: Int) -> Bool {
    age >= 18
}

func label(for battery: Double) -> String {
    if battery < 0.2 { "Зарядіть пристрій" } else { "OK" }   // if-вираз — теж один вираз
}

Щойно в тілі з'являється хоча б ще одна інструкція, return знову потрібен:

Swift
func label(for battery: Double) -> String {
    print("перевіряємо \(battery)")
    return if battery < 0.2 { "Зарядіть пристрій" } else { "OK" }
}
C#

Схоже на expression-bodied member bool IsAdult(int age) => age >= 18;, тільки без =>.

Мітки аргументів і імена параметрів

У Swift у параметра може бути два імені: одне пишуть при виклику (мітка аргументу), друге використовують усередині функції (ім'я параметра).

Swift
func move(from start: Int, to end: Int) {
    print("Рух з \(start) до \(end)")    // усередині — start і end
}

move(from: 1, to: 5)                     // ззовні — from і to

from start: Int читається так: мітка from, ім'я start, тип Int. Навіщо два імені: ззовні виклик звучить як речення англійською («move from 1 to 5»), а всередині змінні мають нормальні імена — print(from) читався б дивно.

Варіанти, які трапляються:

Swift
func greet(name: String) { print(name) }       // одне ім'я — воно і мітка, і ім'я
greet(name: "Ann")

func send(to email: String) { print(email) }   // мітка відрізняється від імені
send(to: "a@b.c")

func square(_ x: Int) -> Int { x * x }          // _ — без мітки
square(4)

_ ставлять, коли зміст аргументу й так зрозумілий з назви функції.

C#

У C# у параметра одне ім'я, і писати його при виклику необов'язково: Move(1, 5) або Move(start: 1, end: 5). У Swift мітки при виклику обов'язкові, і мітка може відрізнятися від імені параметра.

Повне ім'я функції в Swift пишуть разом з мітками: move(from:to:), square(_:). Функції з однаковою назвою, але різними мітками — різні функції.

Значення за замовчуванням

Swift
func spawn(_ kind: String, count: Int = 1, elite: Bool = false) { }
spawn("goblin")
spawn("orc", count: 3)
spawn("dragon", elite: true)

Параметри зі значеннями за замовчуванням зазвичай ставлять наприкінці. На відміну від C#, значення за замовчуванням не обов'язково compile-time константа: це будь-який вираз, обчислений під час виклику.

Variadic-параметри

Тип... дозволяє передати скільки завгодно значень через кому, від нуля й більше. Усередині функції це звичайний масив:

Swift
func track(_ event: String, tags: String...) {
    print("[\(event)]", tags.joined(separator: ", "))   // tags — це [String]
}
track("purchase")                                   // tags = []
track("paywall_view", tags: "onboarding", "variant_b")
C#

Аналог params string[] tags.

Два обмеження:

  • параметр, що йде після variadic, мусить мати мітку — так компілятор розуміє, де закінчується список;
  • готовий масив у variadic передати не можна (у C# з params можна). Якщо таке потрібно, роблять другу версію функції, що приймає [String].

Параметри inout

Звичайна функція не може змінити змінну, яку їй передали: параметри — константи. Якщо функція має змінити саму змінну викликача, параметр позначають inout, а при виклику перед змінною ставлять &. Це майже те саме, що ref у C#:

Swift
func addCoins(_ coins: inout Int) {
    coins += 10
}

var wallet = 50
addCoins(&wallet)
print(wallet)          // 60
C# Swift
void AddCoins(ref int coins) func addCoins(_ coins: inout Int)
AddCoins(ref wallet) addCoins(&wallet)

Функція може змінити й кілька змінних одразу:

Swift
func applyHit(_ damage: Int, to health: inout Int, shield: inout Int) {
    let absorbed = min(shield, damage)   // скільки шкоди забрав щит
    shield -= absorbed
    health -= damage - absorbed          // решта — у здоров'я
}

var hp = 100, shield = 30
applyHit(50, to: &hp, shield: &shield)
print(hp, shield)   // 80 0

Передати в inout можна лише те, що можна змінити: var-змінну, властивість, елемент масиву. let чи число — ні.

А для класів? Щоб змінити властивості об'єкта класу, inout не потрібен: функція отримує посилання на той самий об'єкт. inout з класом потрібен лише тоді, коли треба замінити сам об'єкт на інший:

Swift
final class Player { var hp = 100 }

func hit(_ p: Player) { p.hp -= 20 }             // змінює той самий об'єкт — без inout
func reset(_ p: inout Player) { p = Player() }   // підміняє об'єкт — потрібен inout

На практиці inout пишуть нечасто: у Swift зазвичай просто повертають нове значення (wallet = withBonus(wallet)).

Функціональні типи

Кожна функція має тип, складений з типів параметрів і результату: (Int, Int) -> Int, () -> Void, (String) -> Bool.

Використання

Функцію можна покласти в змінну, константу чи словник і викликати пізніше. Тип виводиться автоматично:

Swift
func roundDown(_ price: Double) -> Double { price.rounded(.down) }
func roundToNine(_ price: Double) -> Double { price.rounded(.down) + 0.99 }

let strategy = roundToNine            // тип виведено: (Double) -> Double
strategy(41.3)                        // 41.99

let strategies: [String: (Double) -> Double] = [
    "control": roundDown,
    "variant_b": roundToNine,
]
let priceForUser = strategies["variant_b"]?(19.4)   // Optional(19.99)

Мітки аргументів не є частиною функціонального типу, тому через змінну функцію викликають без міток.

Як тип параметра

Функцію можна передати в іншу функцію як аргумент. Функцію, що приймає іншу функцію, називають функцією вищого порядку — ти постійно користуєшся ними в C#: list.Where(x => ...).

Swift
func applyTwice(_ f: (Int) -> Int, to value: Int) -> Int {
    f(f(value))
}

func increment(_ x: Int) -> Int { x + 1 }

print(applyTwice(increment, to: 5))   // 7

Тип параметра f — (Int) -> Int: «будь-яка функція, що приймає Int і повертає Int», тобто Func<int, int> у C#. Ми передаємо increment без дужок — не викликаємо, а віддаємо саму функцію. Усередині:

  1. f(5) → increment(5) → 6;
  2. f(6) → increment(6) → 7.

Як тип результату

Функція може й повертати функцію. Наприклад, один раз обрати форматер за валютою, а потім багато разів ним користуватися:

Swift
func formatter(for currency: String) -> (Double) -> String {
    func uah(_ v: Double) -> String { "\(v) ₴" }
    func usd(_ v: Double) -> String { "$\(v)" }
    func plain(_ v: Double) -> String { "\(v) \(currency)" }

    switch currency {
    case "UAH": return uah
    case "USD": return usd
    default: return plain
    }
}

let format = formatter(for: "UAH")   // 1. отримали функцію uah — нічого ще не форматується
print(format(99.9))                  // 2. викликали її → "99.9 ₴"
print(format(10))                    // 3. і ще раз → "10.0 ₴"

Тип результату (Double) -> String означає, що formatter повертає не рядок, а функцію, яка вміє перетворити число на рядок.

C#

Функціональні типи — це Func<double, string>, Action<string> і так далі. Аналог formatter у C# повертав би Func<double, string>. Різниця лише в синтаксисі: у Swift будь-яку функцію можна покласти в змінну чи передати без обгортки.

Вкладені функції

Функцію можна оголосити всередині іншої. Вона невидима ззовні, але бачить змінні зовнішньої функції. Так зручно ховати допоміжну логіку, потрібну лише в одному місці:

Swift
func validatePassword(_ password: String) -> [String] {
    var problems: [String] = []

    func require(_ condition: Bool, _ message: String) {
        if !condition { problems.append(message) }   // бачить problems
    }

    require(password.count >= 8, "Щонайменше 8 символів")
    require(password.contains(where: \.isNumber), "Хоча б одна цифра")
    require(password.contains(where: \.isUppercase), "Хоча б одна велика літера")
    return problems
}

Вкладену функцію можна й повернути назовні — тоді вона захоплює змінні зовнішньої функції. Про це в уроці про замикання.

Перевір себе

Обери відповідь — одразу побачиш, чи правильно, і пояснення.

1. Що означає -> Bool в оголошенні функції?

Тип результату пишуть після стрілки.

2. Чому тут помилка компіляції?

Swift
func discount(for level: Int) -> Int {
    if level > 10 {
        return 20
    }
}
print(discount(for: 5))

Якщо level <= 10, функції нічого повернути. Компілятор вимагає return на кожному шляху.

3. Для чого @discardableResult?

За замовчуванням Swift попереджає про невикористаний результат. Атрибут вимикає це там, де ігнорувати нормально.

4. Коли можна не писати return?

Щойно в тілі з'являється ще одна інструкція, return знову потрібен.

5. Як викликати func move(from start: Int, to end: Int)?

При виклику пишуть мітки (from, to), а імена (start, end) використовують у тілі.

6. Що надрукує цей код?

Swift
func spawn(_ kind: String, count: Int = 1) {
    print(kind, count)
}
spawn("orc")

Параметр зі значенням за замовчуванням можна пропустити.

7. Яке твердження про variadic-параметр tags: String... неправильне?

Готовий масив у variadic передати не можна. Для цього роблять другу версію функції з [String].

8. Що надрукує цей код?

Swift
func addCoins(_ coins: inout Int) {
    coins += 10
}
var wallet = 50
addCoins(&wallet)
print(wallet)

inout дозволяє функції змінити змінну викликача. При виклику ставлять &.

9. Що надрукує цей код?

Swift
func applyTwice(_ f: (Int) -> Int, to value: Int) -> Int {
    f(f(value))
}
func double(_ x: Int) -> Int { x * 2 }
print(applyTwice(double, to: 3))

f(3) → 6, потім f(6) → 12. Функцію передано як значення, без дужок.

10. Що повертає функція з типом -> (Double) -> String?

Функції — значення, тож функцію можна повернути й викликати пізніше.

11. Що правда про функцію, оголошену всередині іншої функції?

Так ховають допоміжну логіку, потрібну лише в одному місці.

Практика
  1. Напиши func clamp(_ value: Double, min: Double = 0, max: Double = 1) -> Double і виклич з різними наборами аргументів.
  2. Напиши func normalize(_ values: inout [Double]), що ділить усі значення на максимум.
  3. Напиши функцію pipeline(_ steps: ((Int) -> Int)...) -> (Int) -> Int, яка повертає композицію переданих функцій.
  4. Придумай API для функції, що переміщує предмет з одного слота інвентарю в інший, так щоб виклик читався природно. Порівняй з тим, як би це виглядало в C#.
