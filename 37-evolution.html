Як розвивається Swift

Зміни мови проходять відкритий процес Swift Evolution: кожна пропозиція (SE-NNNN) публікується на форумі swift.org, обговорюється спільнотою й приймається чи відхиляється командою мови. Тексти всіх пропозицій лежать у репозиторії swiftlang/swift-evolution, і це найкраще джерело, якщо треба зрозуміти, чому щось влаштовано саме так.

Великі версії виходять приблизно раз на рік разом з новим Xcode (вересень), проміжні — навесні.

Swift 1–4: формування мови (2014–2017)

  • 1.x — перший реліз, тісна прив'язка до Objective-C.
  • 2.0 — guard, defer, do-catch/throws замість NSError**, розширення протоколів, #available.
  • 3.0 — великий злам сумісності: нові правила іменування API («Swift API Design Guidelines»), мітка першого параметра стала обов'язковою, прибрано ++/-- і C-подібний for, fileprivate/open.
  • 4.0 — Codable, key paths \Type.prop, багаторядкові рядки, String знову колекція символів.
  • 4.1–4.2 — умовна відповідність протоколам, синтез Equatable/Hashable, CaseIterable, @dynamicMemberLookup, @inlinable, random(in:).

Swift 5.x: стабільність і нові парадигми (2019–2024)

  • 5.0 — стабільний ABI: рантайм Swift вбудовано в iOS 12.2+, застосунки більше не несуть бібліотеку мови з собою. Result, сирі рядки #"..."#.
  • 5.1 — непрозорі типи some, property wrappers, неявний return в однорядкових функціях, стабільність модулів (бінарні фреймворки).
  • 5.2–5.4 — callAsFunction, key path як функція, @main, кілька trailing closures, result builders.
  • 5.5 — Swift Concurrency: async/await, Task, групи задач, актори, @MainActor, Sendable, AsyncSequence.
  • 5.6–5.7 — ключове слово any, @preconcurrency, скорочений if let x, регулярні вирази-літерали й Regex, some у параметрах.
  • 5.8 — поступове ввімкнення майбутніх можливостей через прапорці -enable-upcoming-feature.
  • 5.9 — макроси, if/switch як вирази, пакети параметрів (each T), noncopyable-типи (~Copyable), consume, модифікатори borrowing/consuming, рівень доступу package, visionOS.
  • 5.10 — повна перевірка data races (опційно), вкладені протоколи.

Swift 6.x: безпека за замовчуванням (2024–2026)

  • 6.0 — режим мови Swift 6 з обов'язковою перевіркою data races під час компіляції, типізовані помилки throws(E), рівні доступу на import, Swift Testing (@Test, #expect).
  • 6.1 — кінцеві коми в списках параметрів, аргументів і generic-параметрів, покращення nonisolated для типів і розширень.
  • 6.2 — «доступна конкурентність»: опційні ізоляція на головному акторі за замовчуванням і поведінка nonisolated(nonsending) (вмикаються налаштуваннями), @concurrent для явного паралелізму; InlineArray і цілочисельні generic-параметри, Span для безпечного доступу до неперервної пам'яті, сирі ідентифікатори у зворотних лапках.
  • 6.2.x — атрибут @export для контролю того, що бачать клієнтські модулі.
  • 6.3 — проміжний реліз з покращеннями компілятора й діагностики.
  • 6.4 (Xcode 27) — поточна версія, яку описує книга; документацію доповнено описом body-макросів, сирих ідентифікаторів і протоколів з вимогою суперкласу (сама можливість існує давно).

Як читати старий код

Бачиш у коді Що це і чим замінити
completion: @escaping (Result<T, Error>) -> Void API до Swift 5.5; сьогодні — async throws -> T
DispatchQueue.main.async { } до Concurrency; сьогодні — @MainActor або await MainActor.run
ObservableObject + @Published + @StateObject до iOS 17; сьогодні — @Observable + @State
if let x = x до 5.7; сьогодні — if let x
протокол як тип без any до 5.6; сьогодні — any P або краще some P
@UIApplicationMain застарілий; сьогодні — @main
fatalError в обробці відомих помилок краще throws(E) або Result
NSError і inout NSError? Objective-C стиль; сьогодні — throws
Порада

Перед використанням нової можливості перевір дві речі: яка мінімальна версія компілятора (Xcode) її підтримує і чи потрібна їй підтримка в рантаймі ОС (тоді доступність обмежена версією iOS). Мовні можливості, що працюють лише під час компіляції (як if let x чи макроси), доступні на будь-якій iOS.

Практика
  1. Знайди на GitHub iOS-проєкт 2019–2020 років і перелічи місця, які сьогодні написали б інакше.
  2. Відкрий репозиторій swiftlang/swift-evolution і прочитай мотивацію пропозиції про if/switch-вирази.
  3. Перевір у налаштуваннях свого Xcode-проєкту режим мови й Default Actor Isolation.
